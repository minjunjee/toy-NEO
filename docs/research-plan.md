# 연구 계획

2026-11-20 KST. Claude Code가 썼다. 사용자가 "연구 계획 구체화해봐"라고 해서 쓴 첫 판이고, 사용자와 claude.ai 채팅의 Claude가 고치면 그쪽이 우선한다. 근거가 되는 사실은 `docs/facts.md`에, 이 계획에 이른 논의는 `docs/discussion-2026-11-20.md`에 있다.

## 1. 무엇을 하는 연구인가

메인 주제는 evaluation이다. NEO가 배운 codebook과 executor, 곧 NEO의 theory가 좋은지를 판단하는 방법을 만든다. 지금 있는 판정은 transfer 정확도 하나다. scaling은 그 아래의 일이다. object의 수, program의 길이, primitive의 수를 키운 상황이 NEO가 틀리는 모습을 보여 주는 자리가 된다.

방법은 관찰에서 시작한다. 더 어려운 상황에서 지금 NEO를 돌려 어떻게 틀리는지를 먼저 본다. 틀리는 모습을 종류별로 나누고, 종류마다 그것을 잡아내는 측정을 만든다. 측정이 쓸모 있는지는 그 뒤에 시험한다. 새 부품은 관찰이 가리킬 때까지 만들지 않는다.

## 2. 무대와 모델

무대는 랩의 BabyTheorist다. object의 수, program의 길이, primitive의 수가 모드와 레벨로 나뉘어 있고, 과제마다 정답 program이 파일에 함께 들어 있어서 진단에 쓸 수 있다. 정답 program은 학습 신호로 쓰지 않는다.

모델은 랩 NEO를 그대로 쓴다. 바꾸는 것은 데이터 때문에 바꿀 수밖에 없는 설정값뿐이다. 격자 크기를 10에서 15로, 색의 수를 9에서 10으로 바꾼다. codebook의 code 수는 랩의 GridWorld 설정이 primitive 넷에 code 여섯을 준 비율을 따라 primitive 여덟에 열둘로 시작하기를 제안한다. program의 최대 길이 4와 state의 크기는 랩 설정 그대로 둔다. 이 값들은 Claude Code의 제안이고, 랩이 논문에서 쓴 설정을 받으면 그것으로 바꾼다.

## 3. 순서

### 3.1 준비

할 일은 넷이다. 랩 NEO 코드를 이 레포에 들여온다. BabyTheorist의 HDF5 파일을 읽어 NEO가 받는 형식으로 넘기는 dataset 부품을 쓴다. 아래 표의 설정마다 데이터를 만든다. 설정 하나로 학습을 짧게 돌려 스텝 하나의 시간을 재고 전체 시간을 어림한다.

랩 NEO 코드를 들여오는 일은 레포의 공개 여부가 정해진 뒤에 한다. 이 레포는 지금 공개이고 랩 코드는 내부 코드다.

### 3.2 첫 관찰: 격자를 다시 그릴 수 있는가

NEO는 state encoder와 state decoder를 먼저 학습해서 얼려 두고 쓴다. 그래서 가장 먼저 볼 것은 이 둘이 15칸 격자를 그대로 다시 그리는지다. object가 하나, 둘, 셋인 격자에서 각각, 다시 그린 격자가 원래와 완전히 같은 비율을 잰다.

이것을 먼저 보는 이유가 있다. 여기서 틀리면 그 뒤의 모든 정확도가 함께 낮아지고, program이나 code의 문제와 구별되지 않는다. 랩 설정의 state는 32차원 token 하나인데, 이 크기가 15칸 격자와 여러 object를 담는지는 모른다.

### 3.3 둘째 관찰: 기준 설정에서 NEO가 어떻게 틀리는가

object 하나, 기본 primitive 여덟, 레벨 1에서 NEO를 seed 셋으로 학습한다. 이 설정이 나머지 모든 비교의 기준이다.

### 3.4 셋째 관찰: 한 방향씩 키운다

기준 설정에서 한 가지만 바꾼 설정을 나란히 돌린다. seed는 셋씩이다.

| 방향 | 기준과 다른 것 | 데이터 |
|---|---|---|
| 기준 | 없음 | `single-A` 레벨 1 |
| program의 길이 | 레벨이 2, 3으로 오른다 | `single-A` 레벨 2와 3. 정해진 절차대로 레벨 1을 통과한 모델이 이어서 배운다 |
| primitive의 수 | primitive 하나가 더 있다 | `single-B` 레벨 2를 `single-A` 레벨 2와 견준다. 길이의 분포는 같고 속 비우기 하나만 다르다 |
| object의 수 | object가 둘이다 | 기본 primitive 그대로 object만 둘인 데이터. 생성 옵션으로 만들 수 있는지 준비 단계에서 확인한다 |

object 방향에는 걸리는 것이 있다. 정식 모드 `multi-A`는 object가 둘이 되면서 primitive도 셋이 함께 늘어서 두 가지가 한꺼번에 바뀐다. 그래서 object의 수만 바꾼 데이터를 생성 옵션으로 따로 만들기를 제안한다. 만들 수 없으면 `multi-A` 레벨 1을 쓰고, 두 가지가 함께 바뀌었다는 것을 결과에 적는다.

길이 방향은 정해진 절차를 따른다. 논문이 보고한 레벨 2에서의 멈춤이 이 절차에서 나온 것이라, 같은 절차로 봐야 같은 현상을 보게 된다.

### 3.5 관찰할 때 기록하는 것

run마다 다섯을 남긴다.

1. 두 정확도를 정답 program의 길이별로 나눈 값. 예시 쌍의 출력을 다시 만드는 비율과 새 입력에 옮겨 실행해 맞히는 비율이다.
2. 틀린 과제 50개의 입력, 정답, 예측 격자를 나란히 그린 그림. 사람이 직접 본다.
3. NEO가 고른 code 번호와 정답 primitive를 센 표. 길이가 1인 과제에서 센다. primitive 하나가 code 몇 개에 나뉘는지와 code 하나가 primitive 몇 개에 쓰이는지가 나온다.
4. code마다 쓰인 횟수. 한 번도 쓰이지 않는 code가 있는지 본다.
5. NEO가 뽑은 program의 길이와 정답 program의 길이를 견준 표.

이 다섯은 새 학습 없이 체크포인트와 평가 파일만으로 계산한다.

### 3.6 관찰에서 측정으로

관찰이 끝나면 틀리는 모습을 종류별로 나눈 목록을 만든다. 종류마다 세 가지를 적는다. 어떤 과제에서 어떻게 틀리는가, 그것이 NEO의 어느 부품을 가리키는가, 그것을 숫자로 잡아내려면 무엇을 재야 하는가.

측정의 후보는 논의에서 이미 나온 것이 있다. code와 primitive의 대응, 학습 때 쓰인 적 없는 state에서 code가 같은 일을 하는지, 정답 program에 해당하는 code들을 길게 이어 실행했을 때의 정확도, programmer가 고른 code의 열이 정답과 같은지, 그리고 배운 executor로 미리 실행해 보며 목표에 닿는 열을 찾는 것이다. 이 가운데 무엇을 만들지는 관찰이 정한다. 관찰에서 나오지 않은 실패를 잡는 측정은 만들지 않는다.

측정을 만든 뒤에는 그것이 쓸모 있는지 시험한다. 측정값들로 transfer 정확도를 다시 계산해서 실제 값과 맞는지 보고, 쉬운 설정에서 잰 측정값이 어려운 설정에서의 정확도를 transfer 정확도보다 잘 맞히는지 본다.

### 3.7 그 뒤

측정이 생기면 scaling을 넓힌다. 같은 측정을 레벨 8까지, 풀리는 primitive 셋 모두, object 셋까지 그린다. 고치는 일은 여기서 시작한다. 측정이 가리킨 실패 하나에 가장 당연한 수정 하나를 넣고, 넣은 모델과 넣지 않은 모델을 같은 측정으로 견준다.

Agent는 이 단계에서 다룬다. BabyTheorist는 입력과 출력의 쌍만 주고 action을 받지 않는다. 그래서 Agent로 재려면 action이 있는 환경이 따로 필요하다. 사용자가 Agent로 무엇을 뜻하는지에 따라 할 일이 달라지므로 그 답을 먼저 받는다.

## 4. 결과에 따라 갈리는 곳

| 본 것 | 다음에 할 일 |
|---|---|
| 격자를 다시 그리지 못한다 | 첫 문제는 state의 표현이다. state의 크기를 키우는 것이 가장 당연한 수정이고, 그 전에 사용자에게 보고한다 |
| 기준 설정에서 이미 정확도가 낮다 | 방향을 키우지 않고 기준 설정에서 기록 다섯을 먼저 본다 |
| 기준 설정은 풀고 길이에서 막힌다 | 논문이 보고한 현상과 같다. 길이별 정확도와 program 길이의 표에서 어디서부터 틀리는지 본다 |
| 기준 설정은 풀고 object가 둘일 때 막힌다 | 틀린 그림에서 두 object를 함께 바꾸는지, 엉뚱한 쪽을 바꾸는지, 격자를 못 그리는지를 가른다 |
| 모든 설정을 대체로 푼다 | 레벨과 primitive와 object를 더 키운다. 논문의 보고와 다르므로 설정의 차이를 먼저 확인한다 |

## 5. 시간

잰 것은 데이터 생성뿐이다. 학습 과제 250,000개를 만드는 데 프로세스 하나로 20분에서 27분으로 어림된다. 학습 시간은 모른다. 준비 단계에서 재고 이 절을 고친다.

## 6. 막혀 있는 것

1. 레포의 공개 여부. 랩 NEO 코드를 들여오려면 정해져야 한다.
2. 랩이 논문에서 쓴 NEO 학습 코드와 설정. 받으면 dataset 부품을 새로 쓰지 않아도 되고 설정을 추측하지 않아도 된다. 받지 못하면 Claude Code가 쓴다.
3. Agent의 뜻. 3.7절까지는 막지 않는다.

## 7. 하지 않는 것

- 관찰하기 전에 NEO에 새 부품을 넣는 것.
- 세 방향을 한 설정에 한꺼번에 키우는 것.
- 이전 레포의 부품을 옮겨 오는 것. codebook을 고치는 재구조화, 잠, 설명 길이로 채점하는 게이트가 그것이다.
- 정답 program을 학습 신호로 쓰는 것.
