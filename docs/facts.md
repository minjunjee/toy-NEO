# 확인한 사실

2026-11-20 KST. Claude Code가 썼다. 연구 계획이 기대는 사실을 근거의 종류와 함께 적는다. 근거는 셋으로 나눈다. 코드를 읽어 확인한 것, 직접 돌려 본 것, 다른 문서에 적힌 것을 옮긴 것이다. 새로 확인한 것이 생기면 이어서 적고, 틀린 것으로 드러나면 지우지 말고 고친 날짜와 함께 고친다.

## 1. 랩 NEO 코드

이전 레포 `minjunjee/neo-vocabulary-restructuring`의 코드를 읽어 확인했다. 그 레포의 첫 commit `b30af0d`가 랩의 GeneralizedL2T 코드를 그대로 들여온 것이다. 이 레포에는 아직 그 코드를 넣지 않았다.

NEO는 부품 다섯으로 되어 있다. state encoder가 격자를 latent state로 바꾸고, state decoder가 latent state를 격자로 되돌린다. programmer는 지금 state와 목표 state를 보고 action vector 하나를 낸다. codebook은 그 vector를 가장 가까운 code로 바꾼다. executor는 state와 code를 받아 next state를 낸다. program은 이 과정을 스텝마다 되풀이해서 만든 code의 열이다.

학습할 때는 입력과 출력의 쌍 하나를 받아 정해진 최대 길이까지 code를 하나씩 뽑아 실행하고, 길이마다의 예측 가운데 하나를 골라 loss를 건다. state encoder와 state decoder는 미리 VAE로 학습해 얼려 둔다. 랩의 GridWorld 설정에서는 state가 32차원 token 하나, codebook의 code가 6개, program의 최대 길이가 4다.

스텝 사이에 state를 넘기는 방법은 설정 `state_update`로 셋 가운데 고른다. executor가 낸 latent state를 그대로 넘기는 것, 격자로 풀었다가 다시 읽는 것, 격자의 확률을 그대로 다시 읽는 것이다. 학습의 기본값은 그대로 넘기는 것이고, 이때 넘긴 state와 다시 읽은 state의 차이를 줄이는 loss가 함께 걸린다. 정식 추론은 학습 설정과 무관하게 스텝마다 격자로 풀었다가 다시 읽는다.

정식 추론은 두 단계다. 예시로 받은 입력과 출력의 쌍에서 code의 열을 뽑는다. 예측이 출력과 같아지는 스텝에서 멈춘다. 그다음 그 열을 새 입력에 실행한다. 추론 함수는 스텝마다 고른 code의 번호도 돌려준다.

평가는 둘이다. 하나는 예시 쌍에서 뽑은 program을 새 입력에 실행한 결과가 정답 격자와 완전히 같은 비율이다. 이 문서들에서는 이것을 transfer 정확도라고 부른다. 다른 하나는 같은 program을 예시 쌍의 입력에 다시 실행해서 출력이 나오는 비율이다. 랩 설정은 이 둘을 평가 집합 셋에서 잰다. 학습과 같은 분포, 학습 때 없던 primitive 조합, 학습 때보다 긴 program이다. 정답 program별로 나눠 세는 옵션이 있다.

랩의 GridWorld 데이터는 과제마다 정답 program을 primitive 이름의 열로 함께 저장한다. 레포에 있는 생성기의 primitive는 이동 넷이다. 평가 코드의 이름표에는 이동 넷에 회전, 좌우 뒤집기, 상하 뒤집기, 색 바꾸기를 더한 여덟이 있고, 이 여덟은 BabyTheorist의 기본 primitive와 같다.

## 2. BabyTheorist

공개 저장소 `ahn-ml/babytheorist`의 설명서와 코드를 읽었고, 생성기를 작게 돌려 보았다. 논문 arXiv 2611.08177은 Claude Code가 직접 읽지 않았다.

과제는 격자 위의 object에 숨은 program을 적용해서 만든다. 학습자는 적용하기 전과 후의 격자만 본다. program의 한 스텝은 셋으로 적힌다. 어느 object를 고를지, 어떤 primitive를 쓸지, 대상이 무엇인지다. 격자는 15칸 곱하기 15칸이고 색은 0부터 9까지이며 0이 배경이다.

모드가 object의 수와 primitive의 집합을 정한다.

| 모드 | object | object를 고르는 방법 | primitive |
|---|---|---|---|
| `single-A` | 1 | 번호로만 | 기본 여덟 |
| `multi-A` | 2 | 번호로만 | 기본 여덟에 색 맞바꾸기, 행 맞추기, 열 맞추기를 더한 열하나 |
| `single-B` | 1 | 번호로만 | 기본 여덟에서 시작해 레벨이 오르면 새 primitive가 풀린다 |
| `multi-B` | 3 | 번호, 색, 위치 같은 여덟 가지 | 열하나에서 시작해 레벨이 오르면 새 primitive가 풀린다 |
| `multi_dev` | 2 | 번호로만 | 이동 넷. 개발용이고 논문에는 쓰이지 않았다 |

기본 여덟은 90도 회전, 좌우 뒤집기, 상하 뒤집기, 다음 색으로 바꾸기, 네 방향 이동이다. 뒤 글자가 B인 모드에서는 레벨 2에서 속 비우기, 레벨 4에서 속 채우기, 레벨 6에서 테두리 더하기가 풀린다. object의 수는 생성 옵션 `--n-shapes`로 따로 바꿀 수 있다고 적혀 있다. 돌려서 확인하지는 않았다.

레벨은 1부터 8까지이고 program의 길이를 정한다. 레벨 하나가 길이 하나는 아니다. 레벨 L의 길이는 L 더하기 1을 중심으로 한 분포에서 뽑고, 80%가 그 값 이하다. `single-A` 레벨 1의 학습 과제 2,000개를 만들어 세어 보니 길이 1이 592개, 길이 2가 1,031개, 길이 3이 157개, 길이 4가 110개, 길이 5 이상이 110개였고 가장 긴 것은 10이었다. 랩 NEO의 GridWorld 설정은 program의 최대 길이가 4이므로, 그 설정을 그대로 쓰면 레벨 1에서도 과제의 5%쯤은 표현할 수 없다.

파일은 HDF5다. 입력 격자, 출력 격자, 격자 크기, object 수, program의 길이, 그리고 정답 program이 JSON 문자열로 들어 있다. 설명서는 길이와 정답 program을 분석과 진단에만 쓰고 학습 신호로 쓰지 말라고 적는다. 평가 파일에는 과제마다 예시 쌍이 2개에서 5개, 풀어야 할 새 입력이 1개 들어 있다. 정식 크기는 레벨마다 학습 과제 250,000개와 평가 과제 10,000개다.

정해진 절차는 이렇다. 레벨마다 먼저 평가를 본다. 정확도가 80% 이상이면 그 레벨의 학습을 건너뛴다. 아니면 그 레벨의 250,000개로 학습하고 다시 평가를 봐서 80% 이상이면 다음 레벨로 간다. 점수는 레벨마다의 가장 좋은 정확도에 100을 곱해 더한 값이다. 평가 방법은 랩 NEO 코드의 두 평가와 같다. 예시 쌍의 출력을 다시 만드는 것과 새 입력에 옮겨 실행하는 것이다. 이 절차를 돌려 주는 `BabyTheoristGym`이라는 틀이 저장소에 있다. action을 받는 환경은 아니다.

생성 속도는 직접 쟀다. 학습 과제 2,000개를 만드는 데 `single-A`가 10초, `multi-A`가 13초 걸렸다. 같은 비율이면 250,000개에 프로세스 하나로 20분에서 27분이다. 큰 크기로 돌려 확인한 것은 아니다.

저장소에는 모델 코드, 학습 코드, 체크포인트가 없다.

이전 레포의 문서에 적힌 논문 내용으로는 NEO를 포함한 모든 기준선이 레벨 2에서 멈췄고, `single-A`에서 NEO의 점수가 136.8이다. 이 둘은 claude.ai 채팅의 Claude가 논문 본문을 읽고 적은 것을 옮긴 것이다.

## 4. 이전 레포에서 넘어오는 것

이전 레포의 결과는 규칙 다섯 개, 한 스텝, object 하나인 작은 세계에서 나왔다. 랩 NEO 본체가 아니라 그 위에 얹은 한 스텝짜리 변형에서 본 것이라, 여기서는 사실이 아니라 가설로만 쓴다.

- code 둘을 이어 실행할 때, 첫 실행의 결과를 격자로 풀었다가 다시 읽고 둘째 code를 실행하면 12번 모두 맞았고, executor가 낸 latent state에 바로 실행하면 맞지 않았다. 랩 NEO의 정식 추론은 이미 다시 읽으므로, 이 가설이 걸리는 곳은 학습 쪽이다.
- 같은 효과가 방향마다 따로인 code 여럿으로 쪼개질 수 있고, 한번 쪼개진 채로 prior가 익숙해지면 합치기 어려웠다.
- sample 하나에 든 executor 실행 수를 세어 보면 비용이 어디서 드는지가 보였다. 측정 방법으로 가져올 수 있다.

자세한 것은 그 레포의 브랜치 `code/two-properties-round-1`에 있는 `docs/reports/2026-11-two-properties-round-1.md`에 있다.
