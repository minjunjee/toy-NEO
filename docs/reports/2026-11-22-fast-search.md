# 부품을 빠르게 찾은 결과와 거기서 드러난 것

2026-11-22 새벽, Claude Code가 썼다. 사용자가 세 가지를 정한 뒤의 작업이다. 부수적인 부품과 설정은 도움 없이 직접 찾는다. 실험은 최대한 가속해서 여러 조건을 한꺼번에 돌린다. 지금은 NEO가 못하는 것을 보이고 이유를 분석하는 데 집중한다. 숫자는 모두 직접 돌려서 잰 것이고 원본은 `docs/reports/first-numbers/onestep_screens.json`과 각 run의 `eval/`에 있다.

## 1. 한 줄 요약

primitive 하나짜리 학습 쌍으로 program 한 단계만 학습한 모델이, 추가 학습 없이 여러 단계 과제를 transfer 83%로 푼다. 여러 단계로 학습한 모델은 랩 설정이든 고친 부품이든 40%에서 멈춘다. NEO의 부품은 primitive를 배우고 이어 쓸 수 있는데, 여러 단계를 한꺼번에 학습하는 방식이 code를 망가뜨린다. 망가지는 길은 둘을 봤다. 단계 사이로 확률을 넘기면 code 두 개가 변환 하나의 주소가 되고, 격자만 넘기면 code가 얼추 하는 단계와 고치는 단계로 나뉜다.

## 2. 속도

학습 한 스텝을 프로파일했다. GPU는 RTX PRO 6000 Blackwell 96GB 두 장이다. 모델은 programmer 198만, executor 119만 parameter로 작은데, token 451개짜리 열을 다섯 단계씩 풀어 돌리면서 스텝마다 kernel을 만 번 가까이 부른다. GPU는 계속 일하지만 행렬곱은 시간의 15%에서 20%뿐이고 나머지는 layer norm, attention, 원소별 연산이다.

| 바꾼 것 | 학습 한 스텝, batch 128 | 초당 쌍 |
|---|---|---|
| 랩 설정 그대로 | 152ms | 840 |
| programmer와 executor의 forward를 `torch.compile` | 88ms | 1,456 |
| programmer를 `token_pair_transformer`로 교체 | 85ms | 1,510 |
| 둘 다 | 44ms | 2,898 |

컴파일은 숫자를 바꾸지 않는다. 첫 스텝의 loss가 2.80432와 2.80433이다. `train.compile: parts`로 켠다. 새 programmer는 state와 목표를 칸마다 token 둘로 늘어놓는 대신 칸마다 이어 붙여 하나로 투영한다. token이 451개에서 226개가 된다. 폭을 128에서 256으로 늘리면 계산은 2.8배인데 시간은 1.2배만 늘었다. 작은 행렬에서는 이 카드가 제 성능을 못 내기 때문이다.

## 3. 빠른 판

primitive 하나짜리 학습 쌍만 쓰고 program을 한 단계로 제한한 학습이다. programmer가 code 하나를 고르고 executor가 한 번 실행한다. 한 스텝의 계산이 다섯 단계짜리의 5분의 1이고, 하나를 혼자 돌리면 5분쯤이다. 부품이 primitive 여덟을 code 하나씩으로 배울 수 있는지만 묻는다. 지금까지 55개를 돌렸다.

| 조건 | 재현 | transfer | 뒤집기 둘의 transfer | 회전 |
|---|---|---|---|---|
| 랩 설정 그대로, seed 둘 | 53%, 17% | 53%, 17% | 15%에서 27% | 43%, 7% |
| programmer만 교체, seed 둘 | 50%, 73% | 38%, 60% | 13%에서 30% | 5%, 80% |
| 넓은 programmer와 안 쓰는 code 다시 뿌리기, seed 둘 | 90%, 96% | 69%, 71% | 20%에서 31% | 29%, 65% |
| 넓은 programmer, 다시 뿌리기 없음, 가중치 평균 끔 | 95% | 89% | 52%, 88% | 76% |
| 넓은 programmer와 넓은 executor, 다시 뿌리기 | 99.5% | 85% | 46%, 43% | 100% |
| 다시 뿌리기, batch 128로 24,000스텝 | 99.7% | 92% | 71%, 90% | 80% |

읽은 것은 넷이다.

첫째, 느리게 배우던 이유는 code를 못 찾아서다. 랩의 programmer를 쓰면 executor의 크기나 학습률과 무관하게 처음 1,800스텝 동안 code를 하나만 쓴다. programmer를 바꾸면 300스텝부터 배우고, 안 쓰는 code를 지금의 programmer 출력으로 다시 뿌리면 code가 전부 쓰인다. 다시 뿌리기는 새 부품 `vq_restart`이고 끄면 랩 VQ와 같다. code로 끌어당기는 힘을 0.25에서 1.0으로 올리면 code 셋에서 멈춰 재현이 20%다.

둘째, 다시 뿌리기는 재현을 올리고 transfer를 깎는다. code 16개를 전부 쓰게 만들어서 뒤집기를 code 다섯에서 일곱 개로 쪼갠다. 같은 모델에서 다시 뿌리기를 끄면 code 12개만 쓰이고 transfer가 70%에서 89%로 오른다.

셋째, 같은 데이터 양이면 작게 자주 갱신하는 쪽이 낫다. batch 512로 6,000스텝과 batch 128로 24,000스텝은 계산량이 같은데 transfer가 71%와 92%다.

넷째, 이동 넷과 색 바꾸기는 모든 조건에서 code 하나로 100% 옮겨 간다. 쪼개지는 것은 뒤집기와 회전이다. 회전은 code 둘이 object의 모양으로 깔끔하게 갈린다. 가로로 긴 object를 돌리는 code와 세로로 긴 object를 돌리는 code가 따로다. executor의 폭을 256으로 하면 회전은 100%가 된다. 뒤집기는 어떤 조건에서도 90%를 넘지 못했다.

## 4. 같은 부품을 본 모델에 쓰면

다섯 단계짜리 본 모델에 위의 부품을 넣었다. 넓고 얕은 새 programmer, 넓은 executor, 다시 뿌리기, 컴파일이다. rollout, 길이를 고르는 규칙, loss, 단계 사이에 넘기는 state는 랩 그대로다. 12,000스텝 일정으로 돌렸고 아래는 도중의 값이다.

| 조건 | 스텝 | 재현 | transfer | primitive 하나짜리의 재현, transfer |
|---|---|---|---|---|
| code 차원 4, 끌어당기는 gradient 끔 | 7,200 | 81% | 13% | 98%, 26% |
| 다시 뿌리기 없음 | 4,800 | 34% | 11% | 53%, 25% |
| 기본 | 7,200 | 18% | 3% | 33%, 8% |

첫 줄의 모델은 랩 설정이 36,000스텝에 닿은 재현에 7,200스텝에 닿는다. 그런데 transfer는 13%다. 이 모델이 primitive 하나짜리 과제에 쓰는 program을 적어 보면 code 하나짜리가 없다. 전부 code 둘이고, 같은 primitive에 쓰는 code 쌍이 수십 가지다. 색 바꾸기에 17가지, 좌우 뒤집기에 78가지다.

이 체크포인트를 두 방식으로 쟀다.

| 6,000스텝 체크포인트, 평가 과제 2,000개 | 재현 | transfer |
|---|---|---|
| 학습 때처럼 칸마다의 확률을 넘김 | 76.3% | 12.4% |
| 격자만 넘김 | 2.3% | 0.9% |

격자만 넘기면 재현이 76%에서 2%가 된다. 이 모델의 설명은 거의 전부 단계 사이로 넘어가는 확률에 실려 있다. code 하나가 격자를 받아 격자를 내는 연산이 아니고, code 두 개가 합쳐져 변환 하나를 가리키는 주소다. 첫 단계는 주소의 앞자리를 확률에 적어 두고 둘째 단계가 뒷자리와 합쳐 실행한다.

보고서 `2026-11-20-first-numbers.md`의 5.11절에서 잠을 넣은 모델에서 본 것과 같은 현상이다. 거기서는 일부였고 여기서는 전부다. 부품을 재현이 빨리 오르는 쪽으로 고를수록 모델이 이 해로 더 곧장 간다. NEO의 학습 목표는 예시를 다시 만들기만 하면 채워지고, 단계마다 격자 위의 연산 하나를 하라는 요구는 어디에도 없다. programmer는 매 단계 목표를 보고 code를 고르므로 code의 열이 목표를 가리키는 주소가 될 수 있다. 빠른 판에서는 단계가 하나뿐이라 이 해가 없고, 그래서 transfer가 높게 나온다.

## 5. 더 긴 program

레벨 1로 학습한 랩 설정의 code 16개 모델을 레벨 3의 평가 과제 10,000개에 시험했다. 학습은 다시 하지 않았다.

| 숨은 program의 길이 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| transfer, 확률을 넘김, program 10단계까지 허용 | 58% | 39% | 24% | 16% | 9% | 5% | 5% | 2% |
| transfer, 격자만 넘김 | 50% | 38% | 25% | 18% | 11% | 12% | 9% | 2% |
| 재현, 확률을 넘김 | 100% | 95% | 90% | 82% | 70% | 61% | 50% | 39% |

transfer는 길이가 하나 늘 때마다 0.65배쯤으로 준다. program을 5단계까지만 허용하든 10단계까지 허용하든 transfer는 17.2%로 같다. 재현은 길이 8에서도 39%가 나오는데 transfer는 거의 0이다.

## 6. 격자만 넘기며 학습한 본 모델

같은 빠른 부품으로 본 모델을 격자만 넘기며 학습했다. code 16개, 다시 뿌리기 없음, 12,000스텝이다. 평가도 격자만 넘긴다.

| 모델 | 재현 | transfer | 숨은 program 길이 1, 2, 3, 4의 transfer |
|---|---|---|---|
| 랩 설정, 36,000스텝, 격자만 넘겨 평가 | 83.2% | 40.0% | 57%, 39%, 28%, 21% |
| 빠른 부품, 랩의 `reencode_hard`, 10,800스텝 | 84.1% | 38.4% | 57%, 35%, 27%, 22% |
| 빠른 부품, `neo_visible_state`, 10,800스텝 | 69.6% | 29.6% | 49%, 28%, 15%, 9% |

21일 밤에 랩의 programmer로 돌렸을 때는 둘 다 20% 근처에서 불안정했는데, 빠른 부품으로는 잘 배운다. 단계 사이로 gradient를 흘리는 `neo_visible_state`보다 끊는 `reencode_hard`가 낫다. 그리고 랩 설정이 36,000스텝에 닿은 자리에 3분의 1의 스텝으로 닿는다. 하지만 transfer는 같은 40% 근처다. 부품을 고쳐도, 통로를 막아도 여러 단계로 학습한 모델은 여기서 멈춘다.

이 모델이 primitive 하나짜리 과제에 쓰는 program을 보면 이유가 보인다. 색 바꾸기와 위로 이동은 code 하나이고 100% 옮겨 간다. 아래로 이동은 과제 321개 가운데 227개가 code 하나인데 그 code의 transfer가 73%이고, 63개는 그 code 뒤에 다른 code 하나를 더 붙인 program이다. 왼쪽과 오른쪽 이동도 같다. 뒤집기 둘은 같은 code 넷을 나눠 쓰고 어느 것도 40%를 넘지 못한다. code가 primitive 하나를 온전히 하는 연산이 아니라, 얼추 하는 단계와 고치는 단계로 나뉘어 있다. 마지막 격자만 맞으면 loss가 0이므로 학습은 이것을 막지 않는다.

## 7. 한 단계로만 학습한 모델은 여러 단계 과제를 푼다

빠른 판의 모델은 primitive 하나짜리 학습 쌍으로, program 한 단계로만 학습했다. 이 모델을 추가 학습 없이 가져와 program을 다섯 단계까지 쓰게 하고 격자만 넘기며 레벨 1 전체를 풀게 했다. 평가 과제 10,000개다.

| 모델 | 재현 | transfer | 숨은 program 길이 1, 2, 3, 4, 5 이상의 transfer |
|---|---|---|---|
| 랩 설정, 여러 단계로 36,000스텝 | 83.2% | 40.0% | 57%, 39%, 28%, 21%, 10% |
| 빠른 부품, 여러 단계로 10,800스텝 | 84.1% | 38.4% | 57%, 35%, 27%, 22%, 12% |
| 한 단계로만 학습, code 16개, batch 512로 12,000스텝 | 87.2% | 83.2% | 97%, 87%, 69%, 62%, 29% |
| 한 단계로만 학습, code 10개, batch 128로 24,000스텝 | 80.6% | 77.2% | 97%, 81%, 56%, 43%, 19% |
| 한 단계로만 학습, code 16개, 다시 뿌리기 | 81.4% | 71.5% | 92%, 76%, 49%, 31%, 12% |

한 단계로만 배운 모델은 primitive 둘이나 셋을 이은 과제를 한 번도 본 적이 없다. 그런데 transfer가 83%다. programmer가 목표를 보고 첫 primitive의 code를 고르고, executor가 깨끗한 격자를 내고, 그 격자를 본 programmer가 다음 code를 고른다. 여러 단계로 학습한 어떤 모델보다 두 배 높다.

더 긴 program에서도 같다. 레벨 3의 평가 과제 10,000개에 program을 10단계까지 허용했다.

| 숨은 program의 길이 | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8 |
|---|---|---|---|---|---|---|---|---|
| 랩 설정, 여러 단계로 학습 | 50% | 38% | 25% | 18% | 11% | 12% | 9% | 2% |
| 한 단계로만 학습, code 16개 | 100% | 86% | 68% | 57% | 47% | 30% | 18% | 19% |

레벨 3 전체의 transfer는 17%와 56%다.

읽은 것은 둘이다.

첫째, NEO의 부품은 primitive를 code 하나씩으로 배울 수 있고, 배운 것을 이어 쓸 수 있다. 여러 단계를 한꺼번에 학습할 때 그것이 망가진다. 6절에서 본 것처럼 code가 온전한 연산이 아니라 얼추 하는 단계와 고치는 단계가 된다.

둘째, 이 결과는 진단이고 벤치마크 점수가 아니다. 한 단계 학습은 숨은 program의 길이를 읽어 primitive 하나짜리 학습 쌍만 골랐다. 벤치마크는 그 정보를 주지 않는다. 길이를 읽지 않고 전체 학습 쌍에 한 단계만 허용해서 학습해도 되는지를 지금 돌리고 있다.

## 8. 길이를 읽지 않고 한 단계 학습을 하면

7절의 학습은 숨은 program의 길이를 읽어 primitive 하나짜리 학습 쌍만 골랐다. 그 정보 없이 전체 학습 쌍에 program 한 단계만 허용해서 학습했다. primitive 여럿짜리 쌍은 한 단계로 재현할 수 없으니 loss만 보탠다. 넓은 programmer, batch 128, 24,000스텝이다.

| code 수 | primitive 하나짜리의 재현, transfer | 다섯 단계로 이어 쓴 레벨 1의 재현, transfer |
|---|---|---|
| 16 | 40.3%, 37.5% | 21.7%, 18.7% |
| 32 | 68.9%, 60.1% | 41.0%, 34.8% |
| 길이를 읽고 고른 경우, 16 | 99.4%, 96.6% | 87.2%, 83.2% |

안 된다. code 16개일 때 여덟 primitive 가운데 색 바꾸기 하나만 90%를 넘고 뒤집기는 4%다. 학습 쌍의 70%가 primitive 여럿짜리라서 code가 그쪽에 쓰인다. 7절의 결과를 벤치마크의 규칙 안에서 얻으려면, 한 단계로 설명되는 쌍을 길이 정보 없이 골라내는 방법이 필요하다.

## 9. 여러 단계 학습은 되는 모델도 망가뜨린다

7절의 한 단계 모델에서 모든 부품을 그대로 가져와 여러 단계 학습을 이어 갔다. 격자만 넘기고, 6,000스텝 일정이다. 시작할 때 이 모델은 레벨 1에서 재현 87%, transfer 83%다.

| 무엇을 학습하나 | 스텝 | 재현 | transfer |
|---|---|---|---|
| 전부 | 600 | 43.3% | 35.1% |
| 전부 | 1,800 | 34.5% | 23.6% |
| 전부 | 2,400 | 23.2% | 15.9% |
| programmer만. codebook과 executor는 얼림 | 600 | 12.4% | 12.4% |
| programmer만 | 3,600 | 5.9% | 5.9% |

600스텝 만에 transfer가 83%에서 35%가 되고 계속 내려간다. codebook과 executor를 얼려 깨끗한 code를 지켜 줘도, programmer만 학습하면 100스텝 안에 학습 정답률이 53%에서 18%가 되고 돌아오지 않는다. 이때 재현과 transfer가 같은 것은 code가 깨끗해서 설명만 되면 옮겨 가기 때문이다. programmer가 code를 고르는 능력을 잃는다.

여러 단계 학습의 gradient는 쓸모없는 정도가 아니라 이미 되는 것을 깨뜨린다. 표의 값은 도중의 값이고 일정이 끝나지 않았다. 학습률이 너무 높아서일 가능성은 아직 가르지 않았다.

## 10. 여러 단계 학습에서 code를 빠듯하게 주면

격자만 넘기는 본 모델에 code를 12개만 줬다. 12,000스텝, 평가 과제 10,000개다.

| code 수 | 재현 | transfer | 숨은 program 길이 1, 2, 3, 4의 transfer |
|---|---|---|---|
| 16 | 84.6% | 38.8% | 58%, 36%, 27%, 22% |
| 12 | 83.5% | 45.5% | 64%, 46%, 32%, 19% |

## 11. primitive를 늘리면

BabyTheorist의 primitive 11개와, 직접 만든 8, 16, 24, 32개짜리 데이터에서 빠른 판을 돌렸다. 넓은 programmer, 다시 뿌리기 없음, batch 128로 24,000스텝이다. 첫 두 열은 primitive 하나짜리 과제, 마지막 열은 그 모델을 네 단계까지 이어 쓰게 한 전체 평가다.

| primitive 수 | code 수 | 재현 | transfer | code 하나로 90% 넘게 옮겨 가는 primitive | 이어 쓴 transfer: 전체, 길이 2 |
|---|---|---|---|---|---|
| 8, 직접 만든 데이터 | 16 | 99.0% | 96.4% | 8개 가운데 7개 | 82.7%, 83.5% |
| 11, BabyTheorist | 22 | 99.9% | 97.9% | 10개 가운데 9개 | 70.8%, 73.1% |

11개까지는 거의 다 된다. 16개부터 무너지고, 무너지는 종류가 정해져 있다.

회전, 뒤집기, 전치는 16개 이상에서 transfer가 8%에서 24%다. 재현도 30%에서 78%이고 primitive 하나에 code가 넷에서 일곱 개 붙는다.

이동은 code의 기준이 바뀌면서 무너진다. primitive 8개와 16개에서는 자기 높이만큼 위로 가는 이동이 code 하나이고 100% 옮겨 간다. 격자의 맨 위까지 붙이는 이동이 더해진 24개에서 28%가 된다. 24개 모델의 code를 보면 위로 가는 code가 primitive가 아니라 칸 수로 나뉜다. 위로 2칸인 과제는 "자기 높이만큼"이 48개, "맨 위까지"가 41개인데 전부 같은 code 하나로 설명된다. 3칸, 4칸, 5칸도 각각 code 하나를 두 primitive가 함께 쓴다. 예시 하나만 보면 "위로 3칸"과 "자기 높이인 3칸만큼 위로"는 구별되지 않는다. 모델이 어느 쪽으로 일반화하는지가 데이터에 섞인 primitive에 따라 달라진다.

모양을 바꾸는 primitive는 잘 배운다. 속 비우기, 테두리 두르기, 두 배로 키우기, 거울처럼 이어 붙이기가 88%에서 100%다.

code를 빠듯하게 주는 것은 BabyTheorist의 8개에서만 통했다. 직접 만든 8개에서는 code 10개 가운데 8개만 쓰이고 재현이 70%로 끝났다. 16, 24, 32개에서도 code를 primitive 수의 1.25배로 주면 재현이 57%에서 80%로 더 낮다. primitive가 많으면 code를 찾는 것부터 모자란다.
