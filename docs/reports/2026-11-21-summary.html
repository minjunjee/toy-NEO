NEO를 BabyTheorist에서 돌려 보고 알게 된 것

무엇을 쟀는지부터 시작해서, 결과가 나온 순서대로 적었다. 오전에 보고한 결론 하나가 저녁에 뒤집혔고, 그 이유가 이 문서의 가운데다.

  1. 랩의 transformer NEO는 BabyTheorist 레벨 1에서 새 입력에 정답을 내는 비율이 40% 근처에서 멈춘다. code를 16개에서 8개로 줄여도, 잠을 넣어도, 잠마다 code를 새로 켜도 이 값은 움직이지 않았다.
  2. 오전에 보고한 "잠 한 번으로 61%"는 잘못 읽은 것이다. 그 모델은 program의 한 단계가 다음 단계에, 격자로 그리면 보이지 않는 정보를 넘겨서 정답을 맞혔다. 그 길을 막고 재면 37%다.
  3. 그래서 지금은 그 길을 학습할 때부터 막은 모델 둘을 돌리고 있다. 결과는 22일 새벽에 나온다.

1무엇을 재고 있나

과제는 BabyTheorist의 레벨 1이다. 15칸 격자 위에 object가 하나 있고, 숨은 program이 그 object를 바꾼다. 숨은 program은 primitive 여덟 가운데 몇 개를 이어 붙인 것이다. primitive는 색 바꾸기, 위아래 뒤집기, 좌우 뒤집기, 회전, 그리고 위, 아래, 왼쪽, 오른쪽 이동이다. 평가 과제의 28%는 primitive 하나짜리이고 50%는 둘짜리다.

과제 하나에는 입력 격자와 출력 격자로 된 예시 쌍이 있고, 같은 숨은 program을 적용해야 하는 새 입력이 하나 있다. NEO의 programmer는 예시 쌍을 보고 codebook에서 code를 하나씩 골라 program을 쓴다. executor는 그 code들을 차례로 실행해 state를 바꾼다.

숫자는 둘을 쟀다. 첫째는 재현이다. 예시 쌍에서 쓴 program을 그 예시의 입력에 실행했을 때 예시의 출력이 칸 하나 틀리지 않고 나오는 과제의 비율이다. 둘째는 transfer다. 같은 program을 새 입력에 실행했을 때 정답과 격자 전체가 같은 과제의 비율이다. 정답은 모델에게 보여 주지 않는다. 재현은 되는데 transfer가 안 되면, 모델이 그 예시 하나에만 맞는 설명을 쓴 것이다.

학습에 든 양은 스텝 수가 아니라 계산량으로 적는다. transformer NEO의 학습 한 스텝은 16.4 TFLOPs이고, 아래의 긴 학습은 36,000스텝에 589 PFLOPs다. GPU 하나로 여섯 시간쯤 걸린다. 값은 모두 직접 돌려서 잰 것이고 평가 과제는 10,000개다.

랩 NEO가 0인 이유는 state에 있다. 32차원 latent 하나로는 15칸 격자를 그대로 다시 그리지도 못한다. object가 하나일 때 격자를 정확히 다시 그리는 비율이 89%이고 셋이면 23%다. latent를 256차원으로 키우면 다시 그리기는 되지만, 그 위에서 MLP가 변환을 배우지 못했다. 칸마다 token을 하나씩 두는 transformer NEO는 격자를 완전하게 다시 그린다. 그래서 그 뒤의 실험은 전부 transformer NEO다.

transformer NEO는 길게 학습하면 예시의 90%를 설명한다. 그런데 새 입력에서 맞는 것은 40%다. 설명한 것의 절반 넘게가 새 입력으로 옮겨 가지 않는다. 이 간격이 그 뒤 모든 실험이 붙잡은 대상이다.

3왜 새 입력으로 옮겨 가지 않는가

primitive 하나짜리 과제 2,774개만 골라서 봤다. 예시 쌍과 새 입력 쌍을 모델에게 각각 따로 설명시키고, 두 설명이 같은 code를 쓰는지 비교했다. 새 입력 쌍의 정답은 이 진단에서만 보여 줬다.

두 쌍을 따로 설명시켰을 때과제의 비율그 가운데 transfer
둘 다 같은 code 하나로 설명된다47%100%
둘 다 code 하나로 설명되는데 서로 다른 code다15%32%
예시는 code 하나로 되는데 새 입력 쌍은 안 된다13%2%
예시부터 code 하나로 설명되지 않는다25%21%

transfer는 같은 code 하나가 어떤 입력에서도 그 primitive를 해낼 때 된다. 실패는 primitive 하나를 code 여러 개가 입력에 따라 나눠 맡는 데서 온다. 예를 들어 색 바꾸기를 object의 색에 따라 code 둘이 나눠 맡는다. 이 모델은 primitive 여덟에 code 열넷을 쓴다. 예시에서 고른 code가 새 입력의 object에는 맞지 않는 쪽이면 틀린다.

4잠을 넣은 실험과 오전의 결론

code를 나눠 맡을 여유를 없애려고 code를 primitive 수와 같은 8개만 줬다. 재현은 68%로 내려가고 transfer는 44%가 됐다.

이 학습을 14,400스텝에서 들여다보니 색 바꾸기가 code 둘을 차지하고 있었다. 남은 primitive 일곱이 code 여섯을 나눠 써야 해서 몇몇은 code를 얻지 못했다. 여기에 잠을 한 번 넣었다. 잠은 학습을 잠깐 멈추고 codebook을 고치는 단계다. 한 일은 둘이다. 겹친 code 둘을 하나로 합쳐서 code 하나를 비운다. 그리고 비운 code를 모델이 아직 설명하지 못하는 학습 쌍 하나에 배정한다. 그 쌍을 보고 programmer가 낸 벡터를 그 code의 벡터로 삼는다. 든 계산은 학습 24스텝 분량이다.

오전에는 이것을 "잠 한 번으로 transfer가 17%p 올랐다"고 보고했다. 다음 절에서 이 읽기가 틀렸다는 것이 드러난다.

5뒤집힌 것. program의 단계 사이로 격자에 보이지 않는 정보가 넘어간다

61%가 나온 모델이 primitive 하나짜리 과제에 어떤 program을 쓰는지 하나하나 적어 봤다. 이상한 것이 있었다. 이 모델은 위아래 뒤집기를 어떤 code 하나로 설명한다. 그리고 좌우 뒤집기를 바로 그 code를 두 번 이어서 설명하고, 그 program은 새 입력에서 85% 맞는다. 그런데 위아래로 두 번 뒤집으면 원래 격자로 돌아와야 한다. 좌우로 뒤집힌 격자가 나올 수 없다.

이유는 랩의 transformer NEO 설정에 있었다. 한 단계가 끝나면 state decoder가 칸마다 색의 확률을 낸다. 다음 단계는 그 확률을 state encoder에 다시 넣어 만든 state에서 시작한다. 격자로 그리면 칸마다 확률이 가장 높은 색만 보인다. 하지만 state에는 나머지 확률이 어떻게 퍼져 있는지도 들어간다. 모델은 그 보이지 않는 부분에 정보를 실어 다음 단계로 넘기고 있었다.

그러니 이 code는 위아래 뒤집기라는 함수 하나가 아니다. 눈에 보이는 격자가 같아도, 넘겨받은 확률이 어떻게 퍼져 있느냐에 따라 다른 일을 한다. 첫 단계가 확률의 2%쯤에 표시를 남기고, 둘째 단계가 그 표시를 읽는다.

긴 학습 다섯을 두 방식으로 다시 쟀다. 하나는 학습할 때처럼 확률을 넘기는 방식이고, 다른 하나는 격자만 넘기는 방식이다. code 하나짜리 program은 두 방식에서 결과가 같다.

이 그림에서 읽은 것은 셋이다.

첫째, 격자만 넘기면 다섯 모델의 transfer가 모두 40% 근처다. code의 수도, 잠도, 잠마다 code를 켜는 규칙도 이 값을 움직이지 못했다. 61%였던 모델은 37%로 다섯 가운데 가장 낮다.

둘째, code가 적을수록 모델이 이 길에 더 기댄다. 격자만 넘겼을 때 재현이 내려가는 폭이 code 16개 모델은 7%p이고, code 8개 모델들은 15%p에서 23%p이고, 잠을 넣은 모델은 35%p다. code가 모자라면 단계 사이의 확률을 code 대신 쓰는 것으로 보인다. 이 문장은 내 해석이고 따로 확인하지 않았다.

셋째, 잠이 준 이득 가운데 진짜인 부분과 아닌 부분이 갈린다. 아래 그림은 잠을 넣은 학습과 넣지 않은 같은 학습을 도중에도 두 방식으로 잰 것이다.

잠 직후인 18,000스텝에서는 두 방식의 값이 같고, 잠을 넣은 쪽이 10%p 앞선다. 비운 code가 오른쪽 이동을 맡게 된 것이고, 이것은 격자만 넘겨도 남는 이득이다. 그 뒤가 문제다. 잠을 넣은 학습은 확률을 넘기는 값만 37%에서 61%로 오르고, 격자만 넘기는 값은 제자리다. 18,000스텝 뒤에 새로 배운 것이 전부 단계 사이의 확률에 기댄 program이라는 뜻이다. 잠을 넣지 않은 학습은 두 값이 함께 올라서 마지막에는 격자만 넘기는 값에서 앞선다.

오전 보고에서 고쳐야 하는 문장 둘

"잠 한 번으로 transfer가 17%p 올랐다"는 확률을 넘길 때에만 맞다. 격자만 넘기면 잠을 넣은 쪽이 5%p 낮다.

"code가 적으면 transfer가 는다"도 확률을 넘길 때에만 맞다. 격자만 넘기면 code 16개가 40.0%, code 8개가 41.8%와 39.8%로 차이가 없다.

이 일은 평가라는 주제에 바로 닿는다. 같은 code 두 번이라는 program은 새 입력의 85%에서 정답을 내므로 transfer 정확도로는 성공이다. 하지만 그것은 격자 위의 연산 둘을 이은 program이 아니다. transfer 정확도 하나로는 이 둘이 구별되지 않고, 두 방식으로 재면 구별된다.

잠은 세 가지 모양으로 돌려 봤다.

지금까지의 증거로는, 설명하지 못하는 쌍에 code를 새로 주는 것만으로는 transfer가 오르지 않는다. 지금 모양의 잠은 답이 아니다.

남아 있는 문제는 따로 있다. 뒤집기 둘과 회전이 어떤 설정에서도 "어떤 입력에서도 통하는 code 하나"를 얻지 못한다. code 8개를 준 seed 43의 학습에서 primitive별 transfer는 색 바꾸기 100%, 위 100%, 아래 98%, 왼쪽 100%, 오른쪽 67%인데, 좌우 뒤집기 12%, 위아래 뒤집기 27%, 회전 11%다. 이동과 색은 배우고 뒤집기와 회전은 못 배운다.

그리고 전체 transfer는 이 수로 거의 정해진다. primitive 둘짜리 과제의 transfer가 하나짜리 과제의 transfer를 제곱한 값과 거의 같았다. seed 43은 예상 39%에 실제 40%였다. 내가 한 산수이고 따로 검증한 것은 아니다. 맞다면 program이 길어서 틀리는 것이 아니라, code 하나를 가진 primitive가 여덟 가운데 다섯쯤이라서 틀리는 것이다.

7지금 돌고 있는 것

위의 다섯 모델은 확률을 넘기며 학습했다. 격자만 넘기는 평가는 그 모델들이 학습 때 겪지 않은 조건이다. 처음부터 격자만 넘기며 학습하면 얼마나 하는지는 아직 모른다. 그래서 그 길을 학습 때부터 막은 학습 둘을 돌리고 있다. 둘 다 code 8개, seed 42다.

끝나면 볼 것은 하나다. 격자만 넘기며 학습한 모델의 transfer가 40%를 넘는가. 넘지 못하면 남는 문제는 6절의 것, 곧 뒤집기와 회전이다.

8아직 모르는 것과 정해 줄 것

랩이 논문에서 BabyTheorist에 쓴 NEO의 설정을 모른다. 이전 문서에 적힌 논문 점수는 레벨 1의 정확도가 수십 %여야 나오는데, 공개된 GridWorld 설정을 그대로 가져오면 위의 숫자가 나온다. 그 설정이나 코드를 받을 수 있으면 지금 가장 값이 큰 정보다.

뒤집기와 회전이 왜 code 하나를 얻지 못하는지 모른다. 이동과 색 바꾸기는 칸의 내용을 그대로 옮기거나 색만 바꾸면 되고, 뒤집기와 회전은 object 안의 칸들을 서로 다른 거리만큼 옮겨야 한다는 차이가 있다. 이것이 이유인지는 추측이고 확인하지 않았다.

정해 줄 것은 하나다. transfer를 앞으로 어느 방식으로 적을지다. 내 제안은 격자만 넘기는 값을 기본으로 삼고, 확률을 넘기는 값을 옆에 함께 적는 것이다. program의 각 단계가 격자에서 격자로 가는 연산이기를 바란다면 그쪽이 맞는 잣대다.
