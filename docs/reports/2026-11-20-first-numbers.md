# 첫 숫자: BabyTheorist 레벨 1에서 지금 NEO가 어디에 있는가

2026-11-20 KST 저녁. Claude Code가 썼다. 사용자가 "그냥 필요한 숫자가 있으면 뽑아보면서 진행해"라고 한 뒤 처음 돌린 것들의 결과다. 숫자의 원본은 `docs/reports/first-numbers/summary.json`과 `docs/reports/arc-ceiling/ceiling.json`에 있다.

## 1. 한 줄 요약

랩 코드를 GridWorld 설정 그대로 BabyTheorist에 가져가면 레벨 1에서 거의 아무것도 풀지 못한다. 랩 NEO는 transfer 정확도가 0이다. transformer NEO는 12,000스텝에서 seed 다섯의 평균이 13.7%이고 seed에 따라 3%에서 25%까지 갈리며, 36,000스텝까지 학습하면 40%에 닿아 멈춘다. 가장 먼저 막히는 곳은 state다. 32차원 latent 하나는 15칸 격자를 그대로 다시 그리지도 못한다.

## 2. 무엇을 돌렸는가

데이터는 BabyTheorist의 `single-A` 레벨 1이다. object 하나, 기본 primitive 여덟이고 학습 과제 250,000개와 평가 과제 10,000개다. 평가 과제마다 예시 쌍이 둘 있다.

모델은 랩 코드에 있는 둘이다. 하나는 랩 NEO다. 격자 전체를 latent 하나로 줄이고 programmer와 executor가 MLP다. 다른 하나는 랩의 transformer NEO다. state가 칸마다 token 하나이고 programmer와 executor가 transformer다.

설정은 랩의 GridWorld config에서 데이터 때문에 바꿀 수밖에 없는 것만 바꿨다. 격자 크기를 15로, 색의 수를 10으로 바꿨다. codebook의 code 수는 랩 NEO에 12개, transformer NEO에 16개를 줬다. 랩 NEO의 CNN state encoder는 10칸 격자만 받아서, 같은 층을 15칸에 맞춘 부품을 새로 만들었다. transformer NEO는 랩 일정의 78,200스텝이 15칸 격자에서 13시간쯤 걸려서 12,000스텝으로 줄였다.

평가는 넷을 쟀다. 예시 쌍에서 뽑은 program이 그 쌍의 출력을 다시 만드는 비율을 재현이라고 부른다. 그 program을 새 입력에 실행해 정답과 완전히 같은 비율이 transfer 정확도다. transfer 정확도는 세 방식으로 쟀다. 랩 평가기 그대로인 것은 새 입력의 정답과 같아지는 순간 실행을 멈추므로 정답을 한 번 엿본다. 엄격한 것은 정답을 보여 주지 않는다. 일관된 것은 예시 쌍마다 program을 뽑아서 다른 예시 쌍까지 가장 많이 맞히는 program을 쓴다.

## 3. 격자를 다시 그릴 수 있는가

state encoder와 state decoder만 학습해서, 다시 그린 격자가 원래와 완전히 같은 비율을 쟀다. object가 하나, 둘, 셋인 격자를 섞어 40,000스텝 학습했다.

| state | object 1개 | 2개 | 3개 |
|---|---|---|---|
| 칸마다 token 하나, transformer NEO의 방식 | 1.000 | 1.000 | 1.000 |
| latent 하나, 32차원, 랩 NEO의 크기 | 0.891 | 0.603 | 0.226 |
| latent 하나, 64차원 | 0.991 | 0.933 | 0.796 |
| latent 하나, 128차원 | 0.999 | 0.989 | 0.969 |
| latent 하나, 256차원 | 1.000 | 0.999 | 0.997 |

랩 NEO의 state 크기로는 object가 하나여도 열 번에 한 번은 격자를 틀리게 그린다. object가 늘면 빠르게 나빠진다. program을 배우기 전에 여기서 이미 정확도의 천장이 생긴다. 512차원은 학습 도중에 발산해서 멈췄다.

## 4. 레벨 1에서의 정확도

seed 셋의 평균이고 평가 과제 10,000개 전부로 쟀다.

| 모델 | seed 수 | 재현 | transfer, 랩 평가기 | transfer, 엄격 | transfer, 일관 |
|---|---|---|---|---|---|
| 랩 NEO, state 32차원, 랩 설정 그대로 | 3 | 1.0% | 0.2% | 0.02% | 0.03% |
| 랩 NEO, state 256차원 | 3 | 0% | 0% | 0% | 0% |
| 랩 NEO, state 128차원, MLP 폭 512 | 3 | 0% | 0% | 0% | 0% |
| 랩 NEO, state 256차원, MLP 폭 1,024 | 3 | 0% | 0% | 0% | 0% |
| 랩 NEO, state 32차원, 이동 넷만 쓰는 데이터 | 3 | 0.1% | 0.02% | 0.00% | 0.00% |
| 랩 NEO, state 256차원, MLP 폭 1,024, 이동 넷만 쓰는 데이터 | 3 | 0% | 0% | 0% | 0% |
| transformer NEO, 12,000스텝 | 5 | 41.6% | 13.7% | 13.7% | 15.2% |
| transformer NEO, 36,000스텝 | 1 | 89.8% | 39.8% | 39.8% | 40.4% |

transformer NEO는 추론할 때 정답을 보지 않는 방식을 쓰므로 랩 평가기의 값과 엄격한 값이 같다. transformer NEO의 12,000스텝 결과는 seed 다섯의 transfer가 7.1%, 24.5%, 17.2%, 3.0%, 16.9%다. 같은 설정인데 seed에 따라 여덟 배까지 다르다. 5.5절에서 보듯 이 일정은 학습이 중간에 끊긴 것이라, 이 차이는 같은 길을 얼마나 갔느냐의 차이로 보인다.

랩 NEO는 어떤 크기로도 배우지 못했다. state를 키우면 격자는 다시 그릴 수 있게 되는데 정확도는 오히려 0이 된다. MLP의 폭을 state보다 넓게 키워도 같다.

state를 넘기는 방식도 확인했다. 랩 NEO는 학습할 때 executor가 낸 latent를 그대로 다음 스텝에 넘기고, 정식 추론에서는 격자로 풀었다가 다시 읽는다. 추론도 그대로 넘기게 바꿔 다시 재면 재현이 32차원에서 1.7%에서 5.2%로, 128차원에서 0%에서 4.2%로 오른다. 두 방식의 차이가 있기는 하지만, 어느 쪽이든 5% 안팎이라 주된 원인은 아니다. 이 비교는 run 하나씩을 평가 과제 3,000개로 잰 것이다.

primitive의 수 때문인지도 확인했다. 이동 넷만 쓰는 데이터를 따로 만들어 랩 NEO를 학습했다. 랩의 GridWorld와 같은 종류의 과제를 BabyTheorist의 격자에 올린 것이다. 여기서도 0에 가깝다. 그러니 랩 NEO가 막히는 것은 primitive가 여덟이어서가 아니다. 격자가 15칸으로 커지고, object가 여러 색의 큰 모양이고, 이동이 object 자신의 크기만큼인 것 가운데 어딘가다.

transformer NEO는 배운다. 다만 느리다. seed 42는 예시 쌍 재현이 6,000스텝에서 6%, 9,600스텝에서 18%, 12,000스텝에서 30%였고, seed 43은 같은 시점에 17%, 52%, 63%였다. 12,000스텝의 일정이 끝날 때까지 오르는 중이었으므로 이 값은 이 모델의 끝이 아니다. 세 배 긴 학습을 돌리고 있다.

transformer NEO의 12,000스텝 값을 정답 program의 길이별로 나누면 이렇다. seed 다섯의 평균이다.

| 정답 program의 길이 | 1 | 2 | 3 | 4 | 5 이상 |
|---|---|---|---|---|---|
| 평가 과제 수 | 2,774 | 5,039 | 1,006 | 644 | 537 |
| 재현 | 58.1% | 41.3% | 29.1% | 19.9% | 8.9% |
| transfer, 엄격 | 26.4% | 11.1% | 5.5% | 3.4% | 1.2% |

길이가 1인 과제에서도 재현의 절반이 안 되는 비율만 새 입력으로 옮겨 간다. program이 길어지면 둘 다 빠르게 떨어진다.

## 5. 틀린 과제를 직접 본 것

그림은 `docs/reports/first-numbers/`에 있다. program이 primitive 하나인 과제만 골라 그렸다.

랩 NEO의 예측은 object가 있어야 할 자리 근처에 모양과 색이 뭉개진 덩어리를 그린다. code를 4개까지 써도 예시 쌍의 출력을 한 번도 정확히 만들지 못해서 항상 최대 길이까지 간다. latent 하나에서 격자를 되살리는 일 자체가 executor를 거치면 무너진다.

transformer NEO의 예측은 모양이 또렷하다. 틀리는 모습이 랩 NEO와 다르다. 이동 과제에서는 object를 옮기기는 하는데 거리가 틀린다. BabyTheorist의 이동은 object 자신의 크기만큼 움직이는 것이라 object마다 거리가 다르다. 그림 아홉 장에서는 모델이 예시 쌍에서 본 거리를 code 여러 개의 열로 적어 두고 크기가 다른 새 object에도 같은 거리를 적용하는 것처럼 보였다. 숫자로 확인하니 이 설명은 일부만 맞는다. primitive 하나짜리 이동 과제 1,305개에서, 새 object의 크기가 예시의 object와 같으면 transfer가 17%이고 다르면 9%다. 크기가 다르면 절반으로 떨어지지만 크기가 같아도 17%뿐이다. 틀리는 것의 대부분은 거리를 옮겨 적는 것만으로는 설명되지 않고, 모델이 아직 이동 자체를 정확히 하지 못한다. 회전과 뒤집기에서는 모양이 거의 맞고 한두 칸이 틀린다. 색 바꾸기에서는 색을 바꾸면서 object를 옮기기도 한다.

## 5.1 code와 primitive의 대응

정답 program이 primitive 하나인 평가 과제에서 primitive마다 셋을 쟀다. 예시 쌍의 출력을 정확히 다시 만든 비율, 그것을 code 하나로 해낸 비율, 새 입력에서도 맞힌 비율이다. 평가 과제 3,000개 가운데 primitive 하나짜리 806개로 잰 값이고 12,000스텝의 마지막 체크포인트다. 모델은 code를 5개까지 쓸 수 있다.

| primitive | seed 42: 재현 | code 하나로 재현 | transfer | seed 43: 재현 | code 하나로 재현 | transfer |
|---|---|---|---|---|---|---|
| 색 바꾸기 | 79% | 67% | 57% | 100% | 100% | 76% |
| 위로 이동 | 31% | 0% | 13% | 94% | 87% | 81% |
| 아래로 이동 | 37% | 0% | 11% | 92% | 83% | 73% |
| 왼쪽 이동 | 46% | 17% | 13% | 90% | 66% | 55% |
| 오른쪽 이동 | 60% | 31% | 17% | 89% | 51% | 42% |
| 좌우 뒤집기 | 39% | 0% | 9% | 76% | 48% | 19% |
| 위아래 뒤집기 | 20% | 0% | 2% | 69% | 23% | 19% |
| 회전 | 30% | 0% | 2% | 39% | 12% | 2% |

세 값의 차이가 틀리는 방식을 셋으로 갈라 준다.

첫째는 아예 설명하지 못하는 것이다. seed 43의 회전이 그렇다. 열에 여섯은 예시 쌍의 출력도 만들지 못한다.

둘째는 설명은 하는데 code 하나가 아니라 여러 개를 이어서 하는 것이다. seed 42의 위와 아래 이동이 그렇다. 셋 중 하나는 재현하지만 code 하나로 재현한 것은 0이다. 이렇게 설명한 것은 새 입력으로 잘 옮겨 가지 않는다.

셋째는 code 하나로 설명했는데도 새 입력에서 틀리는 것이다. seed 43의 좌우 뒤집기가 그렇다. 절반을 code 하나로 재현하지만 transfer는 19%다. 같은 code가 다른 object에서는 같은 일을 하지 않는다는 뜻이다.

code 하나로 재현하는 비율이 높은 primitive일수록 transfer가 높다. 두 seed 사이에서도, 한 seed 안의 primitive 사이에서도 같은 방향이다. transfer 정확도 하나로는 보이지 않던 것이 이 표에서 보인다.

## 5.2 code는 차례로 생긴다

저장된 체크포인트 열 개를 따라가며 같은 표를 다시 쟀다. 그림은 `docs/reports/first-numbers/codes_over_training.png`이고 숫자는 같은 이름의 JSON에 있다.

primitive는 한꺼번에가 아니라 차례로 code를 얻는다. seed 43에서는 색 바꾸기가 3,600스텝에, 위로 이동과 좌우 이동이 7,200스텝에, 아래로 이동과 뒤집기가 8,400스텝에 code 하나로 재현되기 시작했고, 회전은 12,000스텝에 12%로 막 시작됐다. seed 42는 같은 순서를 늦게 따라간다. 12,000스텝에 색 바꾸기와 좌우 이동까지 왔다.

code 하나로 굳기 전에 여러 code로 설명하는 단계를 거친다. seed 43의 위로 이동은 3,600스텝부터 6,000스텝까지 재현이 27%에서 41%로 오르는 동안 code 하나로 재현한 과제가 0이었다. 7,200스텝에 46%, 8,400스텝에 71%가 code 하나가 됐다. 이 굳는 시점에 transfer도 함께 오른다.

그러니 12,000스텝의 결과는 학습이 중간에 끊긴 모습이다. 두 seed의 큰 차이는 서로 다른 결과에 도달한 것이 아니라 같은 길의 다른 지점에 있는 것으로 보인다. 더 길게 학습하면 뒤의 primitive들도 code를 얻는지는 36,000스텝 학습이 보여 줄 것이다. seed가 둘이라 순서가 늘 같은지는 아직 모른다.

## 5.3 진단: primitive 하나짜리 과제만으로 학습하면

transformer NEO가 primitive 하나를 배우는 데서 막히는지, 이어 붙이는 데서 막히는지를 가르려고 돌렸다. 학습 과제 250,000개 가운데 정답 program이 primitive 하나인 74,097개만 골라 seed 42로 12,000스텝 학습했다. 저장된 길이를 써서 데이터를 고른 것이라 정해진 절차 밖의 진단이다.

결과는 예상과 반대다. primitive 하나짜리 평가 과제에서 재현 23.1%, transfer 23.0%에 머물렀다. 배운 primitive가 둘뿐이다. 색 바꾸기는 3,600스텝부터 모든 과제를 code 하나로 재현하고 전부 맞힌다. 오른쪽 이동은 끝에 88%를 재현하고 86%를 맞히는데, code 하나로 재현한 것은 0이고 둘이나 셋을 이어서 한다. 나머지 여섯은 12,000스텝까지 0%에서 4%다.

같은 seed로 길이가 섞인 원래 데이터를 학습한 모델은 같은 과제에서 transfer가 14%였고, seed 43은 44%였다. 쉬운 과제만 준다고 primitive를 더 잘 찾는 것이 아니다.

그러니 지금 막히는 곳은 이어 붙이기가 아니라 primitive를 찾는 일 자체다. 그리고 primitive 하나짜리 과제만 주면 그 일이 더 느려진다. 길이가 섞인 데이터에서는 같은 seed가 같은 시점에 좌우 이동 둘을 code 하나로 재현하기 시작했는데, 여기서는 오른쪽 이동 하나만 그것도 여러 code로 배웠다. 왜 긴 program이 섞여 있는 쪽이 primitive를 더 빨리 찾게 하는지는 모른다. run 하나씩의 비교라 가설이다.

## 5.4 진단: 이동 넷만 쓰는 데이터로 학습하면

transformer NEO를 이동 넷만 쓰는 데이터로 seed 42, 12,000스텝 학습했다. primitive의 종류가 적으면 더 빨리 배우는지를 보려는 것이다.

더 빨리 배우지 않는다. 재현이 24.8%인데 transfer는 2.3%다. 예시 쌍 넷 가운데 하나는 설명하지만 그 설명이 새 입력으로 거의 옮겨 가지 않는다. primitive 하나짜리 과제에서도 code를 넷이나 다섯 쓰는 경우가 3분의 2다. 5.1절의 둘째 방식, 곧 여러 code를 이어서 설명하는 단계에 머물러 있다.

기본 primitive 여덟을 다 쓰는 데이터에서 가장 먼저 code를 얻은 것은 색 바꾸기였다. 이동만 있는 데이터에는 그 쉬운 primitive가 없다. 이동은 object의 크기만큼 움직이는 것이라 code 하나에 담기까지가 오래 걸리는 primitive로 보인다.

## 5.5 길게 학습하면: 설명은 거의 다 하는데 절반만 옮겨 간다

seed 42를 36,000스텝 일정으로 학습했다. 같은 seed의 12,000스텝 일정과는 처음 가중치와 데이터의 순서가 같고 학습률의 일정만 다르다. 10,800스텝 시점에 이미 재현 70%, transfer 28%로, 12,000스텝 일정의 같은 시점인 26%와 7%를 크게 앞섰다. 12,000스텝 일정은 학습률이 일찍 내려가서 primitive를 찾는 것이 늦어진 것이다. 5.2절에서 본 seed 사이의 차이 가운데 일부도 이것일 수 있다.

끝까지 학습한 값은 재현 89.8%, transfer 39.8%다. 학습에 든 계산은 589 PFLOPs이고 6시간 25분이 걸렸다.

| 정답 program의 길이 | 1 | 2 | 3 | 4 | 5 이상 |
|---|---|---|---|---|---|
| 재현 | 98.3% | 93.6% | 85.8% | 74.7% | 36.3% |
| transfer | 56.9% | 38.9% | 27.3% | 18.6% | 8.8% |

transfer는 21,600스텝부터 39%에서 40% 사이에 머물렀고 재현만 계속 올랐다. primitive 하나짜리 과제에서는 예시 쌍을 98% 재현하는데 새 입력에서는 57%만 맞힌다. 예시를 설명하는 것과 그 설명이 옮겨 가는 것은 다른 일이고, 더 학습한다고 좁혀지지 않았다.

primitive별 transfer는 좌우 이동이 100%, 색 바꾸기가 92%, 아래로 이동 64%, 위로 이동 40%, 좌우 뒤집기 31%, 위아래 뒤집기 27%, 회전 13%다.

## 5.6 transfer는 같은 code 하나가 양쪽을 설명할 때 된다

왜 옮겨 가지 않는지를 보려고, primitive 하나짜리 과제마다 예시 쌍과 새 입력 쌍을 각각 따로 설명하게 하고 둘을 견줬다. 새 입력 쌍을 설명할 때는 정답을 쓰므로 이것은 진단용이다. 스크립트는 `scripts/babytheorist/transfer_breakdown.py`다.

| 경우 | 12,000스텝, seed 43 | 36,000스텝, seed 42 | 36,000스텝에서의 transfer |
|---|---|---|---|
| 두 쌍 모두 code 하나로 재현되고 같은 code다 | 34.6% | 46.5% | 100% |
| 두 쌍 모두 code 하나로 재현되는데 서로 다른 code다 | 9.7% | 15.1% | 32% |
| 예시 쌍은 code 하나로 재현되는데 새 입력 쌍은 그렇게 안 된다 | 14.7% | 13.2% | 2% |
| 예시 쌍부터 code 하나로 재현되지 않는다 | 41.0% | 25.2% | 21% |

같은 code 하나가 양쪽을 재현하는 과제는 두 모델 모두 하나도 빠짐없이 transfer에 성공한다. transfer 정확도는 사실상 이 비율이 정한다.

둘째 줄은 primitive 하나가 code 여러 개에 나뉜 경우다. 길게 학습한 모델의 codebook을 보면 이동 넷은 각각 code 하나에 담겼는데, 색 바꾸기는 code 둘, 좌우 뒤집기는 셋, 위아래 뒤집기와 회전도 둘에서 셋에 나뉘어 있다. primitive 여덟이 code 14개를 쓴다. 색 바꾸기의 두 code는 색에 따라 나뉜다. 12,000스텝 모델에서 한 code는 색 1, 2, 5, 8을, 다른 code는 3, 4, 6, 7, 9를 맡았다. 나뉜 뒤집기는 transfer가 0%다.

셋째와 넷째 줄은 code가 그 object에는 통하지 않는 경우다. programmer가 놓친 것이 아니다. programmer가 code 하나로 설명하지 못한 예시 쌍에 code 16개를 하나씩 모두 실행해 봐도, 하나로 재현되는 것은 7%와 1%뿐이었다. 어떤 object에서 통하지 않는지도 나눠 보았다. 12,000스텝 모델에서 위와 아래 이동은 높이가 3 이상이면 전부 되고 2이면 절반도 안 된다. 뒤집기와 회전은 한 가지 색으로 된 object에서는 되는 비율이 높고, 두 가지 색으로 된 object에서는 크게 낮다. 좌우 뒤집기가 89%와 26%다. 쉬운 object부터 되고 어려운 object는 나중에 된다.

## 5.7 나뉜 code를 합치는 잠: 첫 시도는 통과하지 못했다

사용자가 잠을 넣어 보자고 했고, 5.6절의 둘째 줄이 그것이 겨냥할 자리다. 먼저 학습이 끝난 모델에 한 번 적용해 보았다. 스크립트는 `scripts/babytheorist/merge_sleep.py`이고 숨은 program은 쓰지 않는다.

하는 일은 이렇다. 학습 쌍 20,000개를 지금 모델로 설명하게 해서 정확히 재현한 18,062개를 program과 함께 저장한다. code 벡터가 가장 비슷한 쌍부터 후보로 삼는다. 후보마다 한 code에 다른 code의 벡터를 주고 저장된 program의 이름도 바꾼 뒤, 저장된 쌍을 다시 실행하면서 고친다. 고친 뒤에 따로 떼어 둔 저장분을 전처럼 재현하면 합친 것을 받아들이고, 아니면 되돌린다.

고치는 방법 둘을 써 봤고 둘 다 후보 여덟 개가 모두 떨어졌다. 36,000스텝 학습의 32,400스텝 체크포인트에서 돌린 값이다.

| 후보 | 합치기 전 재현 | 합친 직후 | 전체를 다시 학습 | 합친 벡터만 맞춤 |
|---|---|---|---|---|
| 색 바꾸기의 두 code | 100% | 95.2% | 95.9% | 98.1% |
| 좌우 뒤집기의 두 code | 100% | 86.6% | 84.0% | 83.4% |
| 위아래 뒤집기와 회전, 서로 다른 primitive | 100% | 95.8% | 92.4% | 94.2% |

executor와 codebook과 programmer를 저장분 전체로 다시 학습하면 다른 code까지 흔들려서 재현이 오히려 내려갔다. 합친 code의 벡터 하나만 맞추고 나머지를 얼리면 색 바꾸기는 98.1%까지 돌아오지만 통과선인 99%에 못 미친다. 서로 다른 primitive를 합친 후보가 떨어지는 것은 맞는 판정이다.

알게 된 것은 나뉜 code들이 같은 일을 하는 복사본이 아니라는 것이다. executor 안에서 실제로 다른 일을 맡고 있어서, 벡터를 하나로 묶는 것만으로는 합쳐지지 않고 executor가 그 primitive 전체를 다시 배워야 한다. 든 계산은 학습 880스텝 분량이었다.

그래서 다음은 둘이다. 하나는 애초에 나뉘지 못하게 하는 것이다. code를 primitive 수와 같은 8개로 준 학습과 10개로 준 학습을 36,000스텝 일정으로 돌리고 있다. 이것이 transfer를 올리면 합치는 것이 줄 수 있는 이득의 크기를 알게 된다. 다른 하나는 합치기를 학습 도중에 넣고, 합친 뒤 학습을 얼마간 이어 본 다음에 받아들일지를 정하는 것이다. 이것은 아직 만들지 않았다.

## 5.8 계산량으로 그린 학습 곡선

사용자의 제안으로 학습 곡선의 가로축을 스텝이 아니라 학습에 든 계산으로 그린다. `scripts/flops.py`가 학습 한 스텝의 계산을 세고 `scripts/babytheorist/curves_by_flops.py`가 그린다. 그림은 `docs/reports/first-numbers/curves_by_flops.png`다. 학습 스텝 밖에서 쓰는 계산은 method가 로그에 `extra_flops`로 적으면 더해진다.

학습 한 스텝은 랩 NEO가 0.17 TFLOPs, transformer NEO가 16.4 TFLOPs다. transformer NEO의 12,000스텝은 랩 NEO의 39,100스텝보다 계산이 30배 든다. 세는 방법은 순방향 계산을 세어 세 배 한 것이다.

## 6. 학습 시간

랩 NEO는 39,100스텝에 27분에서 33분이다. 여섯 개를 한 GPU에서 함께 돌린 값이다. transformer NEO는 GPU 하나를 혼자 쓸 때 스텝당 0.6초이고 12,000스텝에 2시간이다. autoresearch의 한 바퀴를 transformer NEO로 돌리면 바퀴마다 두 시간이 넘는다. 빠른 바퀴를 돌리려면 더 작은 설정이 필요하다.

## 7. ARC 천장

NEO와 무관하게, BabyTheorist의 진짜 primitive 여덟을 이어 붙이는 것만으로 풀리는 ARC 과제를 셌다. 격자 전체를 object 하나로 보는 경우와 연결된 덩어리를 object로 보고 번호로 고르는 경우를 모두 넣었다.

| 집합 | 과제 수 | 풀린 수 |
|---|---|---|
| ARC-AGI-1 공개 학습 | 400 | 8 |
| ARC-AGI-1 공개 평가 | 400 | 0 |
| ARC-AGI-2 공개 학습 | 1,000 | 8 |
| ARC-AGI-2 공개 평가 | 120 | 0 |

풀린 8개는 격자 전체를 돌리거나 뒤집는 과제가 7개이고, 사각형 셋이 각자 자기 높이만큼 위로 가는 과제가 1개다. ARC-AGI-2 학습의 8개는 ARC-AGI-1에서 넘어온 같은 과제다. program의 길이 제한을 두 배로 늘려도 수는 그대로였다.

이 primitive들을 완벽하게 배운 모델이 ARC에서 닿을 수 있는 선이 이만큼이다. ARC에서 모자란 것은 primitive의 종류와 object를 고르는 방법이다.

## 8. 이 숫자들이 말해 주는 것

첫째, 논문의 NEO 점수는 이 설정으로는 나오지 않는다. 이전 레포의 문서에 적힌 논문 내용으로는 `single-A`에서 NEO가 136.8점이고, 그러려면 레벨 1의 정확도가 적어도 수십 %여야 한다. 랩이 BabyTheorist에 쓴 NEO는 공개된 GridWorld 설정과 다른 모델일 것이다. 그 설정을 받는 것이 지금 가장 값이 큰 일이다.

둘째, 관찰에서 나온 첫 실패는 state다. latent 하나로 줄이는 방식은 15칸 격자에서 표현부터 무너지고, 표현을 키워도 MLP가 그 위에서 변환을 배우지 못한다. 칸마다 token을 두는 방식은 표현이 완전하고 느리게나마 배운다. 이 연구가 붙들 모델은 transformer NEO 쪽이다.

셋째, 랩 평가기가 정답을 한 번 엿본다. 새 입력에 실행하다가 정답과 같아지면 멈추기 때문이다. 엄격하게 잰 값과의 차이를 표에 함께 적었다. 평가를 메인 주제로 삼는 연구라면 엄격한 쪽을 기본으로 써야 한다.

넷째, 아직 모르는 것이 많다. transformer NEO가 충분히 오래 학습하면 어디까지 가는지, code와 primitive가 어떻게 대응하는지, 길이가 2 이상인 program에서 왜 떨어지는지는 긴 학습이 끝나야 볼 수 있다.
