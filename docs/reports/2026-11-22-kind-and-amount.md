# 양을 code에 담을 수 있는가

2026-11-22 저녁, Claude Code가 썼다. 사용자가 낸 생각을 실험으로 옮긴 기록이다. 숫자는 모두 직접 돌려서 잰 것이고 원본은 `runs/queue/amount_table_*.json`과 각 run의 `train.jsonl`에 있다. 따로 적지 않으면 seed 42 하나의 결과다.

## 1. 한 줄 요약

code 벡터를 회전으로 묶어도, 학습에서 뺀 양은 나오지 않는다. 양이 더해져야 한다는 요구를 loss로 걸면 학습이 망가진다. 그런데 양은 이미 executor의 실행 안에 있다. 한 칸 옮기는 code를 네 번 연달아 실행하면, 네 칸 옮기기를 한 번도 학습하지 않은 랩 VQ 모델에서 네 칸 pair가 전부 재현된다. 그래서 program을 code 하나와 실행 횟수로 쓰는 모델을 만들었다. 그 결과는 9절에 있다.

## 2. 사용자의 생각과 실험의 형태

사용자의 생각은 이렇다. 잠에서 action 공간을 일반화할 때 회전이 들어간다면, 회전을 so(n)의 반대칭 행렬에 지수사상을 씌워 나타낼 수 있다. Claude Code가 이것을 세 가지로 좁혀 제안했고 사용자가 해 보라고 했다.

- 회전을 격자 state에 걸지 않고 16차원 code 공간에 건다. 격자에 직접 걸면 90도 회전의 행렬식이 격자 크기에 따라 -1이 되어 지수사상으로 닿지 않는다.
- 종류와 양은 이산으로 둔다. code 하나를 종류 g와 정수 양 t로 부른다. gradient로 배우는 것은 종류마다 하나씩 있는 반대칭 행렬과 시작 벡터뿐이다.
- 재는 것은 하나다. 학습에서 뺀 양이 따라 나오는가.

## 3. 학습 없이 본 확인

먼저 이미 있는 모델을 들여다봤다. primitive 24개를 한 step으로 학습한 모델에서, 위로 1칸부터 5칸까지 옮기는 pair가 가장 많이 고르는 code 다섯 개를 꺼냈다.

- 이웃한 칸 수끼리의 cosine이 0.90, 0.85, 0.86, 0.92다. codebook에서 임의로 고른 두 code의 cosine 평균은 0.00이다.
- 다섯 벡터가 퍼진 정도의 85%가 한 직선에, 95%가 한 평면에 있다.
- 2칸 code를 3칸 code로 옮기는 회전을 한 번 더 적용한 벡터는 학습된 4칸 code와 cosine이 0.94다. 그런데 이 벡터를 executor에 주면 정확히 4칸 옮기는 비율이 32%다. 한 번 더 적용한 5칸은 3%다.

모델은 시키지 않아도 양에 따라 code를 한 평면의 호 모양으로 늘어놓는다. 하지만 executor의 동작은 그 호를 따라 이어지지 않는다. code가 놓인 모양과 executor가 하는 일은 별개다. 스크립트는 이 세션의 임시 폴더에 있었고, 같은 측정을 `scripts/babytheorist/amount_table.py`가 일반화해서 한다.

## 4. 데이터와 조건

`scripts/babytheorist/generate_many_primitives.py --primitives shifts`로 새 primitive 묶음을 만들었다. 네 방향으로 한 칸에서 여섯 칸까지 옮기는 24개다. `data/babytheorist/shifts24_without4`는 네 칸 옮기기 네 개를 학습 파일에서 뺀 것이고 평가 파일에는 24개가 다 있다. `data/babytheorist/shifts24`는 다 넣은 것이다. 학습 15만 과제, 평가 12,000 과제이고 program은 모두 primitive 하나짜리다.

학습은 program 한 step, code 48개, batch 128, 24,000 step, 폭 256인 `token_pair_transformer` programmer, 가중치 평균 없음이다. 앞 보고서의 primitive 수 실험과 같은 설정이다.

## 5. 새 부품 둘

### 종류와 양으로 부르는 codebook

`src/components/codes_orbit.py`, 이름은 `vq_orbit`이다. 랩 VQ에서는 code 48개가 서로 관계없는 벡터다. 이 부품은 code를 종류 g와 정수 양 t로 부르고, 종류마다 16차원 시작 벡터 b_g와 16×16 행렬 M_g만 배운다. A_g = M_g − M_g^T는 반대칭이고 exp(A_g)는 회전 행렬이다. code는 다음과 같이 계산한다.

c(g, t) = exp(t · A_g) · b_g

양 3의 code는 시작 벡터를 같은 회전으로 세 번 돌린 벡터다. 그래서 양 1, 2, 3, 5, 6의 code가 학습되어 A_g와 b_g가 정해지면, 아무도 고른 적 없는 양 4의 code도 위치가 정해진다. 회전이라는 조건은 페널티가 아니라 계산식으로 보장된다.

어느 code를 고르는지와 loss는 랩 VQ 그대로다. programmer 출력에 cosine 거리로 가장 가까운 code를 고르고, commitment 항과 codebook 항을 쓴다. 다른 점은 codebook 항의 gradient가 A_g와 b_g로 가서 같은 종류의 code가 함께 움직인다는 것이다. 대조용으로 직선 위에 놓는 방식과, 번호만 붙이고 벡터는 독립으로 두는 방식을 같은 부품에 넣었다. 독립으로 두면 랩 VQ와 출력이 같다는 것을 테스트로 확인했다.

### 양이 더해지게 하는 학습 항

`src/methods/neo_compose.py`, 이름은 `neo_compose`다. 3절에서 code의 모양만으로는 executor가 따라오지 않았으므로 executor에 요구를 직접 건다. 매 step에서 batch의 입력 격자마다 같은 종류의 code (g, a)와 (g, b)를 무작위로 뽑는다. a + b가 codebook에 있는 쌍만 쓴다. executor가 (g, a)를 실행한 결과를 격자로 읽고, 그 격자에서 (g, b)를 실행한 결과를 목표로 삼는다. 여기에는 gradient를 흘리지 않는다. 그다음 executor가 같은 입력에서 (g, a+b)를 한 번 실행한 출력이 목표와 같아지도록 칸별 cross-entropy로 학습한다. 정답 격자와 primitive 이름은 쓰지 않는다. code 벡터는 이 항으로 학습하지 않는다.

## 6. 결과 1. 구조만으로는 학습하지 않은 양이 나오지 않는다

설명률은 programmer가 고른 code로 executor가 pair의 next state를 정확히 재현한 비율이고, transfer는 그 code를 답을 보여 주지 않은 query에 실행해 맞힌 비율이다. primitive마다 평가 과제 300개로 쟀다.

| | 학습한 20개, 설명 / transfer | 네 칸, code 하나 | 네 칸, code 둘짜리 program | 네 칸, code 하나를 반복 |
|---|---|---|---|---|
| 랩 VQ | 90.5% / 85.7% | 0% / 0% | 51.1% / 42.6% | 100% / 95.3% |
| 회전 codebook | 100% / 100% | 3.4% / 1.7% | 84.0% / 77.9% | 100% / 93.8% |
| 랩 VQ, 네 칸도 학습 | 63.0% / 58.4% | 49.3% / 46.1% | 51.8% / 47.5% | 74.0% / 67.2% |

셋째 열이 이 실험이 물은 것이다. 회전 codebook에서도 네 칸 pair는 code 하나로 설명되지 않는다. codebook의 어느 code를 주어도 네 칸 pair를 재현하는 비율이 8%를 넘지 않았다.

code가 놓인 자리를 보면 이유가 보인다. 같은 종류 안에서 이웃한 양끼리는 이웃한 자리에 앉았다. 왼쪽 1, 2, 3칸이 한 종류의 양 4, 5, 6 자리에, 오른쪽 3, 5, 6칸이 다른 종류의 양 1, 2, 3 자리에 있다. 하지만 종류가 방향과 맞지 않고, 네 칸 자리를 비워 두지 않았다. 오른쪽 5칸이 3칸 바로 옆에 앉았다. 데이터에 네 칸이 없으니 그 자리를 비울 이유가 모델에게 없다.

마지막 행은 참고용이다. 네 칸까지 다 학습한 랩 VQ인데 이 seed는 code를 느리게 찾아 24,000 step에 24개 중 일부만 배웠다. 상한으로 쓸 수 없는 run이다.

## 7. 결과 2. 덧셈을 loss로 걸면 학습이 망가진다

| 형태 | 학습한 20개, 설명 | 네 칸, 설명 | 경과 |
|---|---|---|---|
| 회전 codebook, 처음부터 | 68.7% | 6.0% | 전체 설명률이 33%에서 64% 사이를 오르내림 |
| 회전 codebook, 양에 부호 | 74.4% | 0% | 27%에서 68% 사이를 오르내림 |
| 직선 codebook, 처음부터 | 28.4% | 0% | 14%에서 45% 사이를 오르내림 |
| 독립 벡터, 처음부터 | 0% | 0% | 7,200 step에 56%였다가 9,600 step에 code 하나로 무너짐 |
| 회전 codebook, 3,000 step부터 | 재지 않음 | 재지 않음 | 켜기 전 82%, 켠 뒤 19%, 27%, 33%. 10,500 step에 멈춤 |
| 쓰이는 code로만 목표를 만듦, 회전과 독립 | 재지 않음 | 재지 않음 | 12,000 step과 7,800 step까지 0%. 멈춤 |

아래 넷은 Claude Code가 GPU를 비우려고 손으로 멈췄고 이유를 각 run 폴더의 `STOPPED.txt`에 적었다.

원인은 6절의 code 배치에서 나온다. 이 항은 양 1 자리의 code와 양 3 자리의 code를 이어 실행한 결과를 양 4 자리에 요구한다. 그런데 양 4 자리에는 데이터가 이미 다른 primitive를 앉혀 놓았다. 어느 primitive가 어느 번호에 앉을지는 가장 가까운 code를 고르는 규칙이 우연히 정하므로, 번호의 덧셈과 primitive의 합성은 맞지 않는다. executor가 두 요구를 다 만족하는 길은 code를 무시하는 것이고, 독립 벡터 조건이 실제로 그렇게 됐다. 무너진 뒤 executor가 자기 목표와 일치한 비율은 100%였다.

## 8. 결과 3. 양은 실행 횟수로 이미 들어 있다

6절 표의 마지막 열은 탐색으로 잰 것이다. codebook의 code 하나하나를 한 번에서 여섯 번까지 연달아 실행하고, 실행 사이에는 격자만 넘긴다. 가장 적은 횟수로 support pair를 재현하는 code와 횟수를 고르고, 그것을 query에 그대로 실행한다.

네 칸을 학습하지 않은 두 모델 모두에서 네 칸 pair가 100% 재현됐다. 뽑힌 것은 한 칸 code를 네 번, 또는 두 칸 code를 두 번이다. 회전 codebook 모델에서는 아래로 한 칸 code를 1번에서 6번 실행한 결과가 아래로 1칸에서 6칸 pair를 전부 100% 재현했고 왼쪽과 위쪽도 같다. primitive별로 가장 잘 맞는 code와 횟수 하나를 고정하면 query에서도 100%다. 표의 transfer가 94%에서 95%인 것은 과제마다 처음 찾은 조합을 썼기 때문이다. support 하나만 보면 다른 조합도 우연히 맞는 경우가 있다.

program 한 step으로만 학습한 executor가 같은 code를 여섯 번 이어 실행해도 틀리지 않는다. 양이 더해진다는 성질은 loss로 가르칠 필요가 없고 실행에 이미 있다. 모델에 없는 것은 "이 code를 네 번"이라고 말할 방법이다. 랩 NEO의 방식인 code 둘짜리 program은 네 칸의 51%와 84%를 설명했다. programmer가 본 적 없는 pair에서 첫 code를 잘못 고르는 경우가 남는다.
