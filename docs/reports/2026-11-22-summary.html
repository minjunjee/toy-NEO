NEO가 막히는 곳은 부품보다 여러 단계를 한꺼번에 배우는 방식 쪽이다

어제 정리한 내용에서 많이 바뀌었다. 부품을 직접 찾아 학습을 빠르게 만들었고, 그 과정에서 원인이 한 곳으로 좁혀졌다. 어제의 정리는 docs/reports/2026-11-21-summary.html에 그대로 있다.

  1. primitive 하나짜리 학습 쌍으로 program 한 단계만 학습한 모델이, 한 번도 본 적 없는 여러 단계 과제를 푼다. transfer가 seed 여섯에서 31%에서 84%이고 평균 64%다.
  2. 여러 단계로 학습한 모델은 랩 설정이든, 부품을 고치든, 단계 사이의 통로를 막든 39%에서 46%다.
  3. 그러니 NEO의 부품은 primitive를 배우고 이어 쓸 수 있다. 여러 단계를 한꺼번에 학습하는 동안 code가 primitive가 아닌 다른 것이 된다.

1무엇을 재고 있나

과제는 BabyTheorist의 레벨 1이다. 15칸 격자 위의 object 하나를 숨은 program이 바꾼다. 숨은 program은 primitive 여덟 가운데 몇 개를 이은 것이다. 색 바꾸기, 위아래 뒤집기, 좌우 뒤집기, 회전, 네 방향 이동이다. NEO의 programmer는 예시 쌍을 보고 codebook에서 code를 하나씩 골라 program을 쓰고, executor가 그 code들을 차례로 실행한다.

재현은 예시 쌍에서 쓴 program이 그 예시의 출력을 다시 만드는 과제의 비율이다. transfer는 그 program을 새 입력에 실행했을 때 정답과 격자 전체가 같은 과제의 비율이다. 재현은 높은데 transfer가 낮으면 모델이 그 예시에만 맞는 설명을 쓴 것이다. 숫자는 모두 직접 돌려서 쟀다.

2먼저 속도를 올렸다

학습 하나에 6시간이 걸려서는 아무것도 찾을 수 없었다. 학습 한 스텝을 프로파일해 보니, GPU는 계속 일하는데 행렬곱은 시간의 15%에서 20%뿐이었다. 작은 모델이 token 451개짜리 열을 다섯 단계씩 풀어 돌리면서 작은 kernel을 스텝마다 만 번 가까이 부르고 있었다.

컴파일은 결과를 바꾸지 않는다. 첫 스텝의 loss가 소수 넷째 자리까지 같다. 랩의 programmer는 지금 state와 목표를 칸마다 token 둘로 늘어놓는데, 새 programmer는 칸마다 둘을 이어 붙여 token 하나로 만든다. token이 451개에서 226개가 된다.

그리고 싼 판을 만들었다. primitive 하나짜리 학습 쌍만 쓰고 program을 한 단계로 제한한 학습이다. 계산이 다섯 단계짜리의 5분의 1이고 하나에 5분쯤이다. 이 판으로 지금까지 조건 80개쯤을 돌렸다.

3싼 판에서 찾은 것

싼 판은 한 가지만 묻는다. 부품이 primitive 여덟을 code 하나씩으로 배울 수 있는가. 랩 설정 그대로는 못 한다. 재현이 seed에 따라 53%와 17%다. 이유는 code를 못 찾아서였다. 랩의 programmer를 쓰면 executor를 키우든 학습률을 바꾸든 처음 1,800스텝 동안 code를 하나만 쓴다.

세 가지를 바꾸면 풀린다. programmer를 위의 새것으로 바꾸고 폭을 256으로 넓힌다. 평가에 쓰는 가중치 평균을 끈다. batch를 512에서 128로 줄이고 스텝을 네 배로 늘린다. 계산량은 같다. 이러면 재현이 99%가 된다.

transfer는 codebook의 크기가 정한다.

code가 남으면 모델은 primitive 하나를 code 여러 개로 쪼갠다. 회전을 보면 가로로 긴 object를 돌리는 code와 세로로 긴 object를 돌리는 code가 따로 생긴다. 예시의 object와 새 입력의 object가 다른 쪽이면 틀린다. 남는 code가 적으면 쪼갤 여유가 없어서 transfer가 오른다. 다만 딱 8개만 주면 code를 다 찾지 못한다.

어제 넣었던 잠과 같은 종류의 동작도 여기서 다시 쟀다. 안 쓰이는 code를 다시 뿌려 주면 재현은 빨리 오르지만 code 16개가 전부 쓰이면서 뒤집기가 다섯에서 일곱 개로 쪼개지고, transfer는 89%에서 70%로 내려간다.

4여러 단계로 학습하면 무엇을 해도 40%다

싼 판에서 고른 부품을 다섯 단계짜리 본 모델에 넣었다. 두 가지 일이 생겼다.

단계 사이로 칸마다의 색 확률을 넘기는 랩의 방식으로 학습하면, 재현은 6,000스텝에 76%로 빨리 오르는데 transfer는 12%다. 이 모델은 primitive 하나짜리 과제를 전부 code 두 개짜리 program으로 설명한다. code 하나가 연산이 아니라, code 두 개가 합쳐져 변환 하나를 가리키는 주소다. 주소의 앞자리는 격자에 보이지 않는 확률에 실려 다음 단계로 넘어간다. 단계 사이로 격자만 넘기게 하고 재면 재현이 76%에서 2%가 된다.

그래서 처음부터 격자만 넘기며 학습했다. 이번에는 code가 주소가 될 수 없다. 재현 84%, transfer 38%가 나온다. 랩 설정이 36,000스텝에 닿은 자리에 3분의 1의 스텝으로 닿지만, 같은 자리다. 이 모델의 program을 보면 이동조차 깔끔하지 않다. 아래로 이동 과제의 20%가 "거의 맞는 code 하나에 고치는 code 하나"로 설명되고, 뒤집기 둘은 같은 code 넷을 나눠 쓴다. 마지막 격자만 맞으면 loss가 0이라, code가 얼추 하는 단계와 땜질하는 단계로 나뉘어도 학습은 막지 않는다.

5한 단계로만 배운 모델은 이어 쓸 줄 안다

싼 판의 모델을 추가 학습 없이 그대로 가져왔다. program을 다섯 단계까지 쓰게 하고, 단계 사이로 격자만 넘기며 레벨 1 전체를 풀게 했다. 이 모델은 primitive 둘을 이은 과제를 한 번도 본 적이 없다.

seed에 따라 크게 갈린다. 같은 설정으로 seed 여섯을 돌리면 transfer가 84%, 83%, 77%, 64%, 43%, 31%다. 한 단계 학습에서 primitive를 깨끗하게 배운 seed는 잘 이어 쓰고, code를 6개밖에 못 찾은 seed나 이동이 code 둘로 쪼개진 seed는 못 이어 쓴다. 위 표의 값은 좋은 쪽 seed이고 평균은 64%다.

programmer가 목표를 보고 첫 primitive의 code를 고른다. executor가 깨끗한 격자를 낸다. 그 격자를 본 programmer가 다음 code를 고른다. 따로 가르치지 않았는데 이렇게 이어 간다. 더 긴 program에서도 같다.

이 결과를 읽을 때 조심할 것

한 단계 학습은 숨은 program의 길이를 읽어서 primitive 하나짜리 학습 쌍만 골랐다. 벤치마크는 그 정보를 주지 않으므로 이 83%는 벤치마크 점수가 아니다. 원인을 가르는 진단이다.

길이를 읽지 않고 전체 학습 쌍에 한 단계만 허용해서 학습하는 것도 돌려 봤다. 안 된다. transfer가 code 16개에서 19%, 32개에서 35%다. 학습 쌍의 70%가 primitive 여럿짜리라서 code가 그쪽에 쓰인다. 이 결과를 벤치마크의 규칙 안에서 얻으려면 한 단계로 설명되는 쌍을 길이 정보 없이 골라내는 방법이 필요하다.

반대 방향으로도 확인했다. 이 한 단계 모델에서 모든 부품을 그대로 가져와 여러 단계 학습을 이어 가면, 600스텝 만에 transfer가 83%에서 35%가 되고 2,400스텝에 16%까지 내려간다. codebook과 executor를 얼려서 깨끗한 code를 지켜 줘도, programmer만 학습하면 100스텝 안에 학습 정답률이 53%에서 18%가 되고 돌아오지 않는다. 여러 단계 학습의 gradient는 이미 되는 것을 깨뜨린다. 학습률을 10분의 1로 낮춰도, 랩 loss에서 의심한 항 하나를 꺼도 똑같이 150스텝에서 300스텝 사이에 무너지고, 끝의 transfer는 6%에서 19%다.

왜 그런지에 대한 내 해석은 이렇다. 실험으로 가르지는 않았다. 격자만 넘기면 gradient가 단계를 건너지 못해서 loss는 마지막 단계에만 닿는다. programmer가 받는 신호는 "지금 격자에서 code 하나를 한 번 실행해 최종 목표와 가장 비슷하게 만들어라"다. 목표가 두 단계 이상 떨어져 있으면 이것은 "다음 primitive를 골라라"와 다른 요구이고, 한 단계로 배운 programmer가 잘하던 것을 덮어쓴다.

이 결과가 어제까지의 그림을 바꾼다. NEO가 40%에서 멈추는 이유를 codebook의 크기, 잠, 단계 사이의 통로에서 찾았는데, 그것들은 곁가지였다. 부품은 할 수 있다. 예시 하나를 여러 code로 한꺼번에 설명하도록 학습시키면, 설명만 되면 되는 목표 아래에서 code가 primitive가 아닌 것으로 굳는다.

6primitive를 늘리면 어디가 무너지나

BabyTheorist가 가진 primitive는 object 하나짜리로 11개가 전부라서, 같은 object 모양을 쓰고 primitive를 32개까지 늘린 데이터를 직접 만들었다. 한 칸 이동, 격자 가장자리로 붙이기, 180도와 270도 회전, 전치, 색을 거꾸로 돌리기, 두 배로 키우기, 거울처럼 이어 붙이기 같은 것이다. 싼 판으로 돌렸고, 아래는 primitive 하나짜리 과제의 값이다.

11개까지는 거의 다 된다. 16개부터 무너지고, 무너지는 종류가 정해져 있다.

회전과 뒤집기 계열은 16개 이상에서 transfer가 8%에서 24%다. 재현도 30%에서 78%로 낮고 primitive 하나에 code가 네 개에서 일곱 개 붙는다.

이동 계열은 더 흥미롭게 무너진다. primitive 8개일 때는 "자기 높이만큼 위로"가 code 하나였고 100% 옮겨 갔다. 한 칸 이동을 더한 16개에서도 그대로 100%다. 격자의 맨 위까지 붙이는 이동을 더한 24개에서 28%로 떨어진다. 이 모델의 code를 직접 보니 위로 가는 code가 primitive가 아니라 칸 수로 나뉘어 있다. 위로 2칸인 과제는 "자기 높이만큼"이든 "맨 위까지"든 같은 code 하나가 설명하고, 3칸은 다른 code, 4칸은 또 다른 code다. 두 primitive를 함께 설명하는 더 단순한 기준이 "위로 k칸"이기 때문으로 보인다. 그런데 k는 object의 크기와 위치에 따라 달라지므로 새 입력에서는 틀린다. 예시 하나만 보면 "위로 3칸"과 "자기 높이인 3칸만큼 위로"는 구별되지 않는다. 모델이 어느 쪽으로 일반화하는지는 데이터에 어떤 primitive가 섞여 있느냐에 따라 달라졌다.

모양을 바꾸는 primitive는 잘 배운다. 속 비우기, 테두리 두르기, 두 배로 키우기, 거울 이어 붙이기는 88%에서 100%다. 표는 code를 primitive 수의 두 배로 준 조건이고, 앞의 세 열은 primitive 하나짜리 과제의 값이다. 마지막 열은 그 모델에게 program을 네 단계까지 쓰게 했을 때 primitive 둘을 이은 과제에서 나온 값이다.

program의 길이 쪽도 쟀다. 레벨 1로 학습한 한 단계 모델을 숨은 program이 훨씬 긴 레벨 5와 7에 시험하면 transfer가 39%와 21%다. 길이 5까지는 43%에서 46%를 유지하고, 길이 8에서 10%에서 17%로 떨어진다. 이 모델의 programmer는 두 단계 이상 떨어진 목표를 학습 때 본 적이 없다.

7지금 도는 것과 다음

지금은 여러 단계 모델의 seed를 더 돌리고 있다. 격자만 넘기는 여러 단계 모델을 code 12개와 16개로 seed 둘씩이다. 한 시간쯤 걸리고, 끝나면 두 방식을 seed 평균으로 비교한다.

못하는 것을 보이는 단계에서 지금까지 모은 것은 넷이다. 여러 단계 학습이 code를 망가뜨린다. 한 단계 학습은 길이 정보 없이는 안 된다. primitive가 16개를 넘으면 회전과 뒤집기 계열이 빠지고 이동의 기준이 칸 수로 바뀐다. program이 길어지면 길이 6부터 급히 떨어진다. 고치는 단계로 넘어갈 때 첫 과제는, 한 단계로 설명되는 쌍을 길이 정보 없이 골라내면서 배우는 방법이 될 것으로 본다.

디스크는 /home이 있는 SSD가 58GB, /data가 435GB 남아 있다. 여러 개를 까는 실험은 체크포인트를 하나만 남기고 있다.
