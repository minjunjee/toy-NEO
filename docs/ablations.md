# Ablation 기록

논문의 ablation 절에 옮기기 위한 기록이다. 질문마다 무엇과 무엇을 비교했는지, seed가 몇 개였는지, 숫자와 결론, 날짜, 근거 파일을 적는다. 시간순 경위는 `docs/research-log.md`, 설계를 바꾼 이유는 `docs/decisions.md`, 방법의 자세한 설명은 `docs/project-overview.md` 5절에 있다. 근거 파일 가운데 `docs/results/raw/`는 `runs/queue/`의 결과를 복사한 것이고, `docs/results/code_formation_by_run.json`은 run마다 저장된 평가 전체의 code 형성 표다. 둘 다 `scripts/collect_results.py`로 다시 만든다.

환경은 BabyTheorist 방식의 단일 물체 과제다. primitive 수로 환경 크기를 부른다. 8개 환경은 벤치마크의 기본 primitive이고, 24, 32, 52, 64개 환경은 이 레포의 생성기로 늘린 것이다. 가로세로를 바꾸는 넷은 rot90, rot270, transpose, anti_transpose다. 나머지 17개는 24개 환경에서 그 넷과 세 회전 계열 밖의 primitive를 말한다.

## 2. executor: code가 학습 분포 밖에서도 같은 함수인가

primitive마다 가장 자주 그 primitive를 재현한 code를 정답 code로 두고, 학습 분포에서 점점 멀어지는 state 위에서 한 번 실행한 정확도다. 라벨 없는 대응으로, 모델이 새 물체에서 스스로 보인 code 사이의 되돌림 관계가 유지되는 비율도 쟀다.

## 6. 지금의 최선이 어느 비교에서 나왔는가

code 형성은 1절의 pair 둘 hard EM과 검증 점수로 고르기, 계획은 3절의 꿈 학습과 검증된 실제 pair, 평가 때의 탐색은 3절의 support 검증 탐색과 남은 거리 예측기와 길이로 무게를 준 투표에서 왔다. pair의 묶음은 BabyTheorist 학습 규칙 밖의 신호다. 에이전트 환경에서는 같은 에피소드 안의 관찰이 같은 규칙을 따른다는 시간 구조가 이것을 대신할 수 있다고 보지만, 아직 검증하지 않았다.
